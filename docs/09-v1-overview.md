# 拾光 V1：现有功能与使用流程

> 记录日期：2026-09-27。本文按当前**网页端及其服务端已实现的行为**记录 V1 基线；Android 原生端是独立工程，功能与验证状态另见 [手机端实施报告](mobile/implementation-status.md)。后续版本的设想不算作 V1 功能。

## V1 要解决的事

拾光 V1 把一件事串成「记录原始内容 → 找回并讨论 → 选择值得长期保留的信息 → 把行动列为要事或待办 → 整理成成果」。原始记录是依据；AI 的摘要、判断和草稿需要用户核对。普通记录、长期记忆、要事和每日待办是不同对象，彼此不会自动互相转化。

## 已有功能

| 模块 | V1 可以做什么 | 使用条件与边界 |
| --- | --- | --- |
| 记录 | 新建、编辑、删除、置顶文字记录；添加项目和标签；搜索、按类型/项目/标签筛选；查看 Markdown 正文与原文；浏览器保留未保存的文字草稿。可在记录中添加、粘贴、复制、剪切图片。 | 标题、项目、标签可不填。正文和附件保存到服务端后才会在其他设备显示。Markdown 只影响阅读排版，编辑时仍是原始文本。 |
| 文件与录音 | 导入 TXT、MD、CSV、JSON、文字型 PDF、DOCX、PNG/JPG/WebP/GIF、MP3/WAV/M4A/WebM/OGG；查看或下载原件；网页前台录音。 | 单文件上限 25 MB。图片可由支持视觉输入的已配置模型归纳；音频尚无自动转写，扫描 PDF 也不会自动 OCR。普通局域网 HTTP 下，浏览器录音可能受安全上下文限制。 |
| 电脑文件 | 网页端从已映射的 E 盘浏览文件夹、按文件名搜索，再选择文件导入并尝试归纳；记录中保留电脑原路径。 | 服务端默认映射 WSL 的 `/mnt/e`，也可用 `COMPUTER_FILES_ROOT` 指定其他绝对目录。只在选择导入时复制文件；不是实时双向同步。搜索有扫描数量上限，结果不全时进入具体文件夹继续找。 |
| 内容归纳 | 导入可读取的文字或图片后尝试生成 AI 摘要；记录详情可再次点「AI 归纳」。 | 需要已连接且能处理对应输入的 AI 模型。失败时保留原件并显示错误，不把规则摘要冒充 AI 内容。图片和音频要能被检索，仍需可用的文字内容。 |
| 搭子 | 按话题保存会话、跨天继续或新建话题；结合检索结果回答；手动引用最多 5 条记录/要事；显示引用来源。可做应用内联网分析，或生成可编辑搜索简报并带到 DeepSeek 网页端。 | 同一话题的回答使用该会话最近 6 轮，不自动混入其他话题聊天。应用内联网需 AI 模型和 Brave Search 密钥；网页端搜索简报需用户自己核对、复制、粘贴并开启联网。未连接模型时只能做资料摘录。回答是分析建议，不会替用户执行外部操作。 |
| 长期记忆 | 每轮对话可产生最多 3 条候选；用户勾选确认，未选的丢弃；冲突时选择保留旧记忆或新记忆。也可手动添加、编辑、暂停、恢复和删除。 | 只有已确认且生效的记忆参与后续使用。没有稳定事实时可以不产生候选。记录被修改或删除后，关联记忆会重新待确认或失效。 |
| 要事 | 从记录转为要事，或独立新建；来源记录的图片会复制并显示在要事中。填写标题、摘要、标签、项目、相关要事、等级和约定检查时间；AI 辅助编辑可结合原文与图片生成草稿，再由用户保存。 | 等级由用户选。图片归纳需要支持视觉输入的已配置模型；一次分析的图片总量上限为 20 MB。普通要事到点提醒并等待确认；高等级要事到点尝试 AI 复核并给建议，之后仍由用户确认。提醒显示在应用内；不是系统推送，也不保证服务停止时准点触达。 |
| 每日待办 | 在主页添加、完成、删除当天待办；切换日期看历史，将历史未完成项复制到今天。 | 每天是独立列表，跨天不会自动把旧项标为完成或自动迁移。到点要事会在主页另列为「待你确认的要事」，不会自动写进每日待办。 |
| 成果 | 按项目和时间范围，从已有记录生成工作周报或主题整理；查看引用来源、编辑 Markdown 正文、导出 `.md`。 | 有可用模型时尝试 AI 生成；未配置或内容未通过基本来源校验时显示原文整理稿或明确失败。成果中的判断和引用需要人工核对。 |
| 设置与数据 | 配置模型地址/名称/密钥、测试连接；设置 Brave Search 密钥；改访问口令、空间名称和网页主题；查看 AI 调用日志；导出 JSON 数据。 | JSON 导出包含记录等结构化数据，原始附件需逐条下载。主题只影响当前浏览器。记账只有「规划中」入口，没有账目录入或统计。 |
| 小九 | 网页上的轻量陪伴角色，可互动和简短聊天。 | 不等同于搭子的资料问答、长期记忆或任务执行。 |

## 做一件事的推荐流程

以「参加一场 Ozon 讨论，之后要决定是否尝试开店」为例：

1. **先留下原件。** 在「记录」写下会议笔记，或用「电脑文件」找到 E 盘上的文字、图片、录音并导入。可直接写 Markdown，不必先填项目和标签。保存后打开详情核对原文与电脑来源路径；有可用模型时查看 AI 归纳。录音目前需要自己补充文字，才适合后续检索和讨论。
2. **围绕这个话题分析。** 到「搭子」新建一个“Ozon 开店”话题，引用刚才的记录，提出具体问题，例如“这份讨论里哪些环节最值得先验证？”之后从同一会话继续聊；换主题时新建会话。
3. **需要新近事实时搜索。** 可选「应用内联网分析」（需搜索密钥），或点「整理搜索简报 · 去 DeepSeek 网页端」。后者会整理话题背景、关键信息和问题；先检查准备分享的内容，再复制到 DeepSeek 网页端并打开联网搜索。把外部搜索得到的重要结论核对原始网页后，再写回记录。
4. **决定什么值得留下。** 对话下方若出现长期记忆候选，只确认稳定的个人偏好或持续计划；一次性信息可以全部丢弃。若与旧记忆冲突，当场选择保留哪条。会议发生了什么仍以原始记录为准，不必都转成长期记忆。
5. **把需要跟进的事情单列。** 如果要在指定时间检查“是否完成首批选品验证”，把记录转为「要事」，核对标题和摘要，选择等级并设置时间。高等级到点后查看复核建议，再由自己确认或编辑时间稍后处理。当天可执行的小任务，如“联系三家供应商”，直接放入「今日待办」。
6. **整理与回看。** 一段时间后到「成果」按项目/时间生成周报或主题整理，检查引用，修改后导出 Markdown。回到要事或历史待办，可看到之前约定与完成情况。

对应的最短路径是：**记录 → 搭子引用并讨论 → 人工确认记忆/要事 → 每日待办执行 → 成果回看**。其中第 3–6 步按事情需要选择，不要求每条记录都走完。

## 数据与能力边界

- 服务端以 `.data/shiguang.sqlite` 保存记录正文、要事、会话、记忆状态、成果和待办；上传原件位于 `.data/uploads/`。同一服务地址和访问口令下，网页设备读取同一空间。页面会检查变更并更新，但健康接口返回正常不代表某次文件上传或保存已经成功；以保存成功提示及重新打开后仍能看到内容为准。
- 检索默认可用关键词方式。配置 Qdrant 与 Embedding 服务后，记录和已确认长期记忆可使用 dense 语义与 sparse 词项混合检索；SQLite 仍是权威数据源。没有配置向量服务时，不应把关键词匹配说成语义理解。
- V1 的搭子是“检索资料、组织上下文、调用模型、给出带来源的回答”的早期形态；没有自主执行工具、完整的长期任务规划或可靠的系统级主动提醒。小九聊天与资料问答是两种不同交互。
- V1 目前不提供自动音频转写、扫描件 OCR、记账、系统推送、离线可靠同步、多用户空间。Android 原生端另有实现和限制，本文的网页操作步骤不等于原生端功能验收。

## V1 验收时可走的三条路径

| 场景 | 检查结果 |
| --- | --- |
| 写/导入一条文字记录 | 保存后能重开，原文与 Markdown 排版可切换；搜索能找回；有可用模型时能看到可核对的 AI 归纳。 |
| 引用记录讨论 | 搭子回答能看到引用来源；同一话题退出后能接着聊；记忆候选在用户确认前不生效。 |
| 约定一件要事 | 到点后主页显示待确认提醒；高等级显示复核结果或失败原因；用户确认后状态变为已确认。 |
