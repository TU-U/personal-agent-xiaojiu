# 小九桌宠 plan

版本：2026-09-28 · 对应 [spec](小九桌宠spec.md) · 用户最新示意图与“所有监督提醒绑定小九”补充要求。

本次只同步文档；以下为后续开发步骤，不代表已执行。替代旧版“只维护、不接业务提醒”的计划。

## 1. 目标与依赖

把小九做成统一督促与提醒表达入口，同时保留生活情绪交流。所有提醒走小九提示表和台词，源模块保留详情/确认操作。先统一业务事实与提醒契约，再实现展示与状态反馈，不能各模块写一套自己的小九文案和轮询。

依赖 SUP 的日实例、计时/提醒及三日事实；EVT 的约定检查；REC 的待办和成果路由；MEM 等的待处理状态。短聊天仍复用公共生成接口。查看 09/10/11 及现代码，只迁移需要改变的行为，不重做应用或角色资产。记账提醒以用户原文为准，接入公共契约但不改写记账文件。

## 2. 分步实施

### PET-P01 · P0 · 统一提醒来源、去重与表达契约

- 对应 PET-02、PET-03、PET-08、PET-09；验收 PET-A02、A04、A05、A09。
- 盘点 workRun/task、todo、event、memory-review 和其他已有提醒入口；区分普通操作反馈与监督消息，建立来源矩阵，避免漏接或把所有系统错误都变催促。
- 实现公共只读聚合层与类型（建议新增 `server/pet-reminders.mjs` 或通用 reminders 服务及 `/api/pet/reminders`，名称为设计建议）。每条有源 id/版本、约定/类别去重键、状态、小九台词、处理目标。
- 源模块继续负责定时与业务门槛；聚合器不重新创建日任务或调度一遍。已处理/取消/改期即时反映，稍后与静音按统一规则展示。普通提醒文案用模板，模型不可用仍可工作。
- 原页面保留事实和操作，移除重复的独立主动催促；需要在原处显示督促消息时复用同一条小九消息及身份。
- 代码入口：`server/work-tasks.mjs`、`server/events.mjs`、`server/index.mjs`、`src/TodayTasks.tsx`、`src/TodoPanel.tsx`、`src/Events.tsx`、`src/MemoryReview.tsx`、`src/types.ts`。
- 完成证据：来源清单、最小聚合接口样例、重复轮询/处理/改期后结果，无源实体副作用。

### PET-P02 · P1 · 小九标识、提示表及常驻交互

- 对应 PET-03、PET-04、PET-08、PET-09；验收 PET-A02、A03、A05、A09。
- 基于公共数据源，在角色左上角显示未处理标识；实现一个独立、可滚动的完整提示表。条目包含小九台词和对应处理链接；不要将消息塞入原聊天历史。
- 拆开 `hover/focus`、`pinned`、`loading/error` 和提示数据状态。可见性为“常驻或当前交互区域处于 hover/focus”；从角色移动到表内保持可操作。显式关闭临时表后避免同一焦点立刻重开，下一次主动进入可恢复。
- 「提示语」只切换 pinned；关闭常驻不清空提示。零条显示“无”，失败/旧数据明确标记。不要只截取前三条代替完整表。
- 复用变更通知/合理轮询，卸载清理，不因页面切换创建多套监听；更新文本不造成焦点跳走。
- 代码入口：`src/PetBuddy.tsx`、`src/styles.css`、`src/api.ts`，必要时提取 `src/PetReminderTable.tsx`。
- 完成证据：桌面 hover→移入滚动→常驻→取消→空态/失败态以及键盘操作。

### PET-P03 · P1 · 三入口与生活交流

- 对应 PET-01、PET-05、PET-06；验收 PET-A01、A07、A08。
- 直接点击角色执行摸摸；拖动超过阈值抑制 click。删除独立摸摸按钮/功能区及喂食功能、相关调用和无用状态转换，保留需要的既有素材，不顺手清理用户资产。
- 提供「交流」「汇报」「提示语」三入口。交流打开情绪聊天；调整提示词支持可爱、自然、适量 emoji，不催办每一句闲聊。
- 汇报直接导航成果页，触发反馈但不调用报告生成/证据/确认接口；导航后仍能看到小九，避免重新挂载导致反馈丢失。
- 聊天使用短历史和经 MEM 过滤的相关通用长期记忆，业务提示单独查询。修正页面说明：小九会展示待处理提醒，但情绪聊天不会默认读取所有业务资料。
- 代码入口：`src/PetBuddy.tsx`、`server/index.mjs` 的 pet/chat、`src/App.tsx`、`src/types.ts`、`src/styles.css`。
- 完成证据：三入口正确、无喂食/独立摸摸区；汇报导航无新增产物；失败输入保留，聊天含自然emoji。

### PET-P04 · P0/P1 · 事实驱动的状态反馈

- 对应 PET-07、PET-08；验收 PET-A05、A06、A07。
- SUP 定义并输出“完成事件”和“同一每日任务连续三天未完成”事实，PET 只消费。按 spec 的完整计划日/截止/跳过/改期口径实现，相关计算可独立单测。
- 映射常态、摸摸、任务完成、连续未完成、汇报到现有素材。时间长短是实现默认，不覆盖用户确认的形象要求。
- 给反馈事件 id 或版本去重；初次打开页面不把历史完成任务逐个庆祝。反复轮询不重放三日提醒，遵守跟进上限。
- 情绪状态与提醒标识独立；汇报反馈结束回常态，未处理提示不消失。旧 timeout 必须取消或检查事件版本，不覆盖新反馈。
- 代码入口：`server/work-tasks.mjs`、公共提醒服务、`src/PetBuddy.tsx`，必要时提取 pet state reducer。
- 完成证据：可控时钟覆盖三日边界与计时器竞争，不真实等待三天。

## 3. 迁移与兼容

- 优先聚合已有业务数据，不迁移或复制用户任务、要事及待办。不把移除旧提醒展示理解成删除原业务状态/确认入口。
- 需要持久提醒/反馈去重标识时增量建表或实体，备份后迁移；不把全部历史记录标为新通知。小九收起/提示语开关仅为显示偏好，不是业务确认。
- 保持原有源模块人工确认、安静时段和提醒次数。首次部署与重启用当前事实恢复提示，不能把已处理项复活。
- 不变更 E 盘、手机工程和用户记账文档；不重绘小九角色，不引入系统桌面壳。

## 4. 最小验证与交付

1. 服务端用隔离数据覆盖任务/待办/要事/记忆待处理聚合、去重、确认与改期、稍后/静音、三日规则；只验证真实需要的失败边界。
2. 一条桌面流程覆盖角色点击/拖动、三按钮、hover完整表、常驻切换、长表滚动、空态及失败；一次聊天请求验证上下文隔离和草稿保护。
3. 验证汇报仅导航、完成反馈来自真实确认事件，提醒收起不修改业务数据。无模型时提示表仍工作。
4. 检查相关模块没有独立重复催促；记账未实现时验证契约可接入，不伪造已有账单提醒。
5. 涉及 TS 运行 `npm run check`，交付前一次 `npm run build`；浏览器仅对应 desktop 用例，不运行手机/原生或无关全套测试。

逐项记录 PET-A01–A09 的结果与未满足依赖；不能只把三按钮画出来就算完成。交付需包含提醒来源映射、状态口径、接口、代码改动和可复现证据。

## 5. 不在本轮范围

系统托盘/系统桌面常驻、语音播报、跨设备情绪聊天记忆、聊天模型自动执行业务动作。相关已确认通用长期记忆的只读使用已按 Q10 纳入本轮，不在排除范围内。**全应用监督提醒绑定小九已属本轮需求，不再列为待确认扩展。**

## 桌面版追加计划（2026-10-08 确认，2026-10-09 本机版落地）

2026-10-08澄清：桌面壳复用现有前端、后端及数据存储，不重做一套桌面业务系统。双端同时打开时，先核对现有数据刷新/变更读取机制，仅补缺口；验收在网页保存后桌面读取同一对象、反向同理，并区分共用数据与实时UI更新。保留已有revision冲突与草稿保护规则，不因收到新数据覆盖未保存编辑。


依据spec的“桌面版追加决策”和架构第9.4节实施；旧网页阶段排除桌面壳的条款不排除此后续阶段。

1. 设计桌面壳启动协调：识别并复用兼容的拾光后台，启动所需服务，共享原数据目录，展示启动错误、日志入口及重试。
2. 主窗口关闭仅隐藏；小九窗口与后台继续工作，托盘保留打开入口和独立退出命令。按已确认退出策略检查执行中任务：提供继续后台运行或确认退出，无执行中任务直接退出；确认退出时停止当前执行并保存可用进度，下次展示恢复/重试入口。按已确认服务归属规则保留原本已运行的共享后台，只停止桌面壳自启且当前独占的后台；实现服务归属和使用状态识别，任务收尾按执行归属处理，不影响其他入口的执行。
3. 为桌面小九增加「打开主界面」按钮，与托盘共用主窗口恢复逻辑；已有窗口恢复并聚焦，重复点击不创建多个实例。保持角色摸摸及原三按钮职责。
4. 最小验收覆盖：关闭主窗口后小九和提醒仍可用 → 通过小九按钮恢复主界面 → 再从托盘恢复；重复点击无重复窗口/服务，操作不确认提醒。只做对应桌面场景，不重跑无关全套测试。

5. 增加开机自启入口与设置开关；区分用户双击启动与系统登录自启。自启仅显示小九，后台正常启动或复用，主界面留待用户主动打开。开关默认开启且可由用户关闭，保存用户选择，后续启动/升级不覆盖已关闭的设置；本轮讨论不修改操作系统自启设置。实施时增加默认开启、关闭后保持及自启只显示小九的最小验收。

6. 退出流程只补必要验证：有任务时两个分支、无任务直接退出；退出后重开能看到真实的中断状态与恢复/重试入口，不产生重复业务写入，不将中断伪装为成功。

7. 退出范围定向验收：接入已运行后台后退出桌面壳，网页仍可用；桌面壳启动并独占后台时退出能够正常收尾并关闭；已转为共享的后台及其他入口的任务不被误停。具体识别方案在实施时设计。

本次只更新文档，不启动Electron开发或变更现有进程。
