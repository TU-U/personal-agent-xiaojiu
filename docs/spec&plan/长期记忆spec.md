# 长期记忆 spec

版本：2026-09-28 · 模块编号：MEM · 范围：网页端与服务端。

本文区分现状与目标；“必须”描述待验收规范，不代表代码已全部做到。与 [实施计划](<长期记忆plan.md>) 配套，跨模块规则见 [总索引](README.md)。来源为 [V1 基线](../09-v1-overview.md)、[第二阶段方案](../10-phase2-product-plan.md)、[首轮实施记录](../11-phase2-implementation.md) 与本次代码核对。新设计细节是本次整理的实现目标；未来扩展不能被自动执行器当作已获授权。

## 1. 目标与模块责任

把用户明确确认的稳定背景、偏好和持续计划按需带入相关对话与任务，既能跨天延续，又能说明记住了什么、来自哪里、何时改变。

## 2. 当前实现与缺口

### 已有基础

每轮可提最多三条候选，只从用户陈述提取；对话候选有人工选择和冲突处理。Memories 页支持管理 candidate/active/paused/rejected 等状态。Qdrant 检索 active 记忆，SQLite 保存权威内容；来源记录变化会触发待确认/失效。scope 当前主要是通用、周报、文章。
这不是 skills 管理器：内容描述用户事实/偏好，不是给 Agent 安装执行能力。

### 需要补齐

手动 PATCH 启用/编辑记忆当前缺统一的完整冲突检查路径；冲突模型只看最近有限数量（40/80）的记忆，库大后易漏检。确认内容的版本、并发冲突处理、scope 检索过滤和“实际采用了哪些记忆”的说明需要完善；不能把向量相似直接当矛盾结论。

## 3. 范围与非目标

测试阶段每轮尝试提炼候选，有事实才生成，允许零条；用户不选的在确认后丢弃；一直未处理的候选按 Q09 五轮期限清理。SQLite 管权威记录与状态，Qdrant 存向量/词项索引，不能只有数据库里一段全量 prompt。情节事件在 EVT 用户端可见；会话摘要归 CHAT，执行状态归 ACT，不自动转成长期记忆。

## 4. 用户流程

一轮对话/手动新增 → 提取或填写 candidate → 混合召回可能重复/冲突的 active 记忆 → 判断同义、变更或矛盾 → 用户选择新旧/修改后重新检查 → 原子确认 active → 后台索引 → 相关问题按 scope/状态/主题召回 → 展示采用依据。
暂停/更正/来源失效后立即退出有效读取，不等待向量清理完成。

### Q09 已确认：五轮清理、红点与规范格式

未处理候选在5轮对话后清理，并且存在待处理候选时须有红点提示。实现口径：按候选所属话题计数，一轮指用户消息及其成功返回的搭子回答；候选产生于第 N 轮，在之后第5轮完成（N+5）时过期，其他话题/失败请求/打开页面不计轮数。此计数口径为明确实现默认，不把用户没说明的全局轮数强行当已确认。

到期检查同时发生在继续对话、读取和提交确认时；过期候选不载入模型、不再点亮待处理红点，也不能用旧页面确认。与确认并发时在同一事务判定。用户主动提交选择后，未选项按原规则丢弃，不等待5轮。没有继续对话不按墙上时间擅自清理。实现保留必要的过期/已处理元数据供解释，不将其作为有效记忆。

记忆必须有适用范围，建议固定写入结构为：summary（提炼事实）、scopeKind（global/project/thread）、scopeId（范围对象，global为空）、sourceRef/sourceRevision、candidateBatchId、originTurn、expiresAfterTurn、status、revision、createdAt。有效时间仅来源确有信息才写；summary 不存零散执行指令或助手猜测。用户界面显示摘要、范围、来源和冲突选择。全局/项目/话题是本次范围功能的实现方案，Q04 已确认统一项目入口，项目范围使用共享 projectId，不按项目名猜ID。

激活必须校验范围合法、对象存在、来源有效、候选未过期并完成冲突检查；范围扩大或修改正文重新走候选确认。旧“通用/周报/文章”不能无声变成同义的三种范围，迁移保留旧用途标签，不能把原限周报的内容扩大到所有话题。

## 5. 数据与状态契约

memory：id、content、scope、status、sourceRef/sourceRevision、createdAt、updatedAt、revision；扩展 confirmedAt、supersedesId、conflictRefs、validFrom/validTo（确有时间信息才写）、decisionReason。候选批次绑定 conversationId；同一批次确认有幂等键。
状态：candidate → active/rejected；active → paused/invalid/被替代；修订 active 文本先生成待确认新版本，不静默覆盖。被替代内容保留审计，不同时对当前事实生效。

本节新增字段是目标契约，不是已落地 schema。实现时优先兼容既有实体，迁移前备份，禁止为了符合新字段丢弃历史数据。

## 6. 功能与异常要求

| 编号 | 要求 | 具体行为 |
| --- | --- | --- |
| MEM-01 | 生成边界 | 只提用户明确陈述的稳定事实/偏好/持续计划，不把助手回答、工具结果、临时问题或推测当用户记忆。无稳定信息时显示无候选；模型失败可见。 |
| MEM-02 | 选择后生效 | 所有新增与更正先候选；只有用户确认的所选条目生效，未选条目在提交后丢弃。手动入口和对话入口遵守同一规则。 |
| MEM-03 | 混合召回冲突 | embedding + 关键词找候选冲突，并按事实主体/主题/时间判断；同义重复、过期更新、实际矛盾分开。不能只看固定最新 N 条，也不以相似分数自动覆盖旧记忆。 |
| MEM-04 | 当场解决与原子提交 | 存在冲突时展示新旧及依据，用户选择保留哪个；同批候选互相冲突也要处理。新旧版本发生并发变化时重新核对，检查失败不得绕过启用。 |
| MEM-05 | 状态和范围 | 读取时再校验 SQLite 的 active、scope、来源有效性和版本；暂停、删除、失效或被替代立刻排除。不同话题可共享相关稳定背景，不混入无关全部记忆。 |
| MEM-06 | 可见与可纠正 | 用户能看到内容、来源、状态及被采用场景，能暂停、编辑候选、恢复或删除。恢复到 active 也要检查当前冲突，不把历史事实无条件复活。 |
| MEM-07 | 独立责任 | 会话摘要不是长期记忆、要事不是技能、任务日志不是人格；自动索引不等于用户批准。向量库可重建，不作为唯一存储。 |
| MEM-08 | 候选期限与红点 | 未处理候选五轮后清理；有效待处理有红点、过期退出提示；期限及并发在服务端核验，未确认不生效。 |
| MEM-09 | 规范范围格式 | 摘要、适用范围、来源与版本等结构化写入；按范围召回，修改/扩大范围重新检查，旧用途字段不能无声扩大。 |

## 7. 验收标准

| 编号 | 场景 | 可检查结果 |
| --- | --- | --- |
| MEM-A01 | 人工门槛 | 生成候选后调用下一轮检索，尚未确认不能被引用；选一弃二后只有所选 active。 |
| MEM-A02 | 跨入口冲突 | 对话确认、手动新增、编辑和恢复都能发现旧库中的同一事实冲突；超过80条仍不因截断漏掉已知测试冲突。 |
| MEM-A03 | 并发确认 | 两个候选同时替换同一旧事实只能形成合法结果，迟到确认返回可解释冲突，不出现互相矛盾的 active。 |
| MEM-A04 | 即时失效 | 暂停或来源删除时即使 Qdrant 未清理，也不能载入上下文；恢复需要再次核查。 |
| MEM-A05 | 语义与词项 | 不用完全相同措辞仍能找到相关背景，专有名词可精确召回；返回采用记忆及其 scope，不把闲聊无关信息全载入。 |
| MEM-A06 | 五轮边界 | 同话题第N+4轮仍待处理，第N+5轮过期；其他话题/失败请求不计；过期确认被拒绝且保留可解释结果，红点与有效待处理数一致。 |
| MEM-A07 | 范围合法性 | 全局/项目/话题匹配正确；未知scopeId拒绝；候选、过期、暂停和不适用内容不载入；旧用途限制不因迁移消失。 |

“已有测试通过”仅代表其覆盖的路径；模型请求能返回、页面能打开或接口 health 正常，不足以证明整个模块达标。

## 8. 依赖与后续边界

依赖 RET 的相关召回和 SET 模型能力；确认/版本规则先稳定，再开放给 CHAT/RES/成果读取。不依赖小九，也不以会话摘要代替冲突检索。

P2：自动遗忘、无需确认的记忆写入、自动推断性格及无条件全库 prompt 均不启用。四类记忆是责任划分，不要求机械新建四套数据库。

## Embedding 选型补充：使用 Qwen

用户已于 2026-09-29 确认选用 **`Qwen/Qwen3-Embedding-0.6B`**，采用本地部署、完整 1024 维向量，供长期记忆与资料检索共用。该选型已确认，不再是待选建议；模型在本机的速度和检索准确率仍需迁移时实测。4B/8B 不属于本次默认选型，不自动升级。

Qwen Embedding 负责 dense 语义向量，关键词 sparse 与 Qdrant RRF 融合继续保留。长期记忆正文、确认状态与来源仍由 SQLite 管理。记忆和资料查询使用匹配的模型与预处理，不能用普通 Qwen 聊天模型代替专用 Embedding 模型。

此前 BGE-M3 是已有实现基线，不因文档更新自动替换。切换需新建模型/维度/预处理版本明确的 Qdrant 索引，全量重算相关向量并验证后再切流；维度相同也不能混用不同模型的向量。

依据：[Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)、[官方 GGUF 版本](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B-GGUF)。

## 过滤与校验补充（2026-09-29）

遵守 [校验审查中的共同契约](../14-filter-validation-review.md)：候选、已选与可提交使用一致规则；无效已选项必须可见可移除；模型建议不等于有效业务数据。以下是目标约束，不代表代码已修复。

- **V01：** 模型返回值先校验对象结构、类型、长度、枚举及引用。标题/摘要/分类等业务内容超限不能无提示截断；无效必填字段显示具体原因。模型不能写 priority、confirmed、active、revision 等人工/服务端字段。关联建议可过滤去重，但必须返回被移除项的原因；用户已确认输入不能静默过滤。
- **V02：** 候选列表、已选列表和提交校验共用类型/空间/状态/自身排除规则；候选缺页不代表对象失效。已有选项即使不在当前页，也须显示摘要或失效占位及移除入口。提交时重新核验，失败保留草稿，按字段及具体 ID 返回原因。
- **V05：** 索引命名空间绑定实际模型版本/维度/预处理/分段版本；异步写入前后核验源版本，陈旧任务不能清掉新任务。记忆冲突检查合并尚未索引的有效数据库变更；无法保障覆盖时保留候选并阻止激活，不把部分检索说成检查完成。
- **V18：** 冲突结果必须通过完整 schema：无冲突必须显式合法 null；有冲突必须命中本次有效候选、对应主体/范围/时间且带依据。陌生ID/缺字段是检查失败，不是无冲突；保留候选并允许重试，不激活、不删旧记忆。
- **V19：** 所有入口共用检查；编辑排除自己的旧版本而非所有同主题条目，比较当前批次与适用范围有交集的active记忆及未索引变更。确认事务重新校验批次/选项/替换对象/版本，整体提交或整体失败；不凭客户端conflictId直接删对象。检查不完整时不激活。

## Q04 已确认：统一项目入口

用户已在对话中确认：点击 PersonalAgent，可以一起找到相关笔记、要事、项目文件及其他项目内容；不同来源的搭子会话各自保留，不合并。

共享 project 使用稳定 ID；项目类别显式关联 projectId，各模块按同一 ID 查询，不能用名称相同猜测关系。入口按内容类型分组且可分页，分别显示空/加载/失败，部分模块失败不能把整个项目说成无内容。旧项目字符串保留，映射不明确的先显示待关联，不静默合并同名项目；改名不改变 ID、引用或 threadId。聚合页面不等于把项目全量资料送入每次聊天，模型仍按问题、范围和预算读取。
