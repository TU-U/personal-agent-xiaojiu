# 要事 spec

版本：2026-09-29 · 模块编号：EVT · 范围：网页端与服务端。

本文区分现状与目标；“必须”描述待验收规范，不代表代码已全部做到。与 [实施计划](<要事plan.md>) 配套，跨模块规则见 [总索引](README.md)。来源为 [V1 基线](../09-v1-overview.md)、[第二阶段方案](../10-phase2-product-plan.md)、[首轮实施记录](../11-phase2-implementation.md) 与本次代码核对。新设计细节是本次整理的实现目标；未来扩展不能被自动执行器当作已获授权。

## 1. 目标与模块责任

把重要经历与需要约定检查的事情显式保存给用户查看；在约定时间由高等级事项获得复核建议，所有事项最终都由用户确认。

## 2. 当前实现与缺口

### 已有基础

event 已有标题/摘要/标签/项目、normal/high 等级、关联要事、sourceNoteId、dueAt、open/confirmed 状态。从记录创建时复制图片快照；AI 辅助编辑可读原记录与图片。`server/events.mjs` 定时检查到期高等级事项，保存复核文本或失败原因，主页显示到期待确认项。

### 需要补齐

目前到期复核主要使用摘要与来源文字，没有充分联动关联任务进度、证据、其他要事和图片已有解释；事件修改与迟到复核结果的并发需持续保护。稍后确认、历史调整轨迹和情节回顾信息结构可增强。reviewedDueAt 只代表检查过，不表示用户确认。

## 3. 范围与非目标

要事同时承载用户可见的情节/重要经历记录及约定检查，不是 Agent 隐藏记忆。与普通 todo、workRun 和稳定语义记忆分开；高低等级始终由用户确定。

## 4. 用户流程

记录转要事/独立新建/对话候选 → 编辑标题、摘要、标签、项目、相关事件建议及图片 → 可请求 AI 辅助草稿 → 用户核对并保存长期/一次性、等级及可选检查时间 → 有约定时到点检查 → 普通事项提醒；高等级追加建议 → 用户确认本次检查或选某日某时稍后确认 → 可约下一次或显式结束要事 → 回看经历与处理历史。

### 已确认：直接进入固定搭子会话（2026-09-29）

所有要事提供“与搭子讨论”入口，点击自动引用并跳转：首次建立关联，以后一直返回同一会话，跨天、改名和编辑正文都不另开。重新进入时引用最新已保存版本，既有对话和历史引用版本保留。关联按来源类型与稳定 ID 保存，不按标题或版本创建；共用 CHAT 的幂等映射接口，不在本模块另造会话规则。详见 [搭子 spec](搭子spec.md) 的“从来源回到固定讨论”。本条为确认目标，尚待开发。

### 已确认答复：要事为两种时长 × 两个等级

来源：[Q05/Q06](../13-requirements-answers.md)。新增 eventType=long_term/one_off，与 priority=normal/high 独立，共四种组合：长期普通、长期高等级、一次性普通、一次性高等级。两项都由用户选，不由 AI 自动改变。

- 纯经历可以不设检查时间；无时间就没有到期提醒，包括高等级也不虚构约定。安排提醒时才校验具体日期时间。
- 要事本身的进行/结束状态，与每一次约定检查的待确认/已确认/稍后状态分开保存。确认提醒只确认本次检查，不自动结束整件要事；结束要事是明确用户动作。
- 长期要事可继续约下一次检查；一次性也不因看过提醒就被宣称已完成。下一次时间由用户设置，不自动假定每日/每周周期；频率未指定不自行生成无限提醒。
- 每次检查使用独立 occurrenceId、dueAt、复核输入版本和确认时间；同次稍后调整约定，旧结果失效。历史确认不随新检查覆盖。旧 confirmed 可作为旧检查已确认迁移，不能猜测整件要事已结束。
- 高等级仅在有约定且到期时给主动建议，普通只提醒；所有到期提醒仍人工确认。模型失败保留提醒而不伪造复核成功。
- 从记录 A 创建要事 B，B 使用自己的固定搭子会话，不沿用 A；可以引用来源，但不自动复制全部历史或合并两段会话。

## 5. 数据与状态契约

沿用 event；保留图片独立快照、来源引用及原件校验。目标补充 relatedTaskIds、timeline/变更记录、reviewSnapshot（所看资料/计划版本）、reviewStatus 和 snoozeHistory。dueAt 是约定检查时刻，不默认为事件发生日期，可另设 occurredAt（兼容为空）。
旧 open/confirmed 仅作为迁移输入；目标分离要事生命周期与检查实例状态，不能用一个 confirmed 同时代表看过提醒和事情结束。

本节新增字段是目标契约，不是已落地 schema。实现时优先兼容既有实体，迁移前备份，禁止为了符合新字段丢弃历史数据。

## 6. 功能与异常要求

| 编号 | 要求 | 具体行为 |
| --- | --- | --- |
| EVT-01 | 显式经历记录 | 用户可在要事页浏览、搜索和编辑历史经历；既可由普通记录转来，也可直接填写。来源图片形成独立快照，源记录删除不让要事图片消失。 |
| EVT-02 | 辅助编辑先草稿 | AI 从文字和图片提标题/摘要/标签/项目及相关事件建议，用户编辑确认后保存。不能未经核对覆盖原文或生成不存在的关联 ID。 |
| EVT-03 | 用户定等级 | 仅 normal/high 两级，用户选择；AI 可解释关注点，不能自动升级降级或把关联任务交付算作已确认。 |
| EVT-04 | 到约定时间检查 | 到期前不做约定复核；普通只提醒，高等级才主动检查事情记录与计划的遗漏/矛盾并给建议。结合存在的关联任务/成果时注明证据和版本。 |
| EVT-05 | 所有提醒人工确认 | 无论等级都等用户确认本次检查；AI 返回“暂无问题”不自动确认，也不自动结束要事。用户可指定日期与具体时分稍后检查，旧时间的复核结果不能覆盖新约定。 |
| EVT-06 | 可解释与可重试 | 建议显示依据、生成时间、失败信息；模型不可用仍有到期提醒。重复调度不反复调用同一版本，用户可显式重试。 |
| EVT-07 | 跨模块关联 | 与话题/任务/成果建立引用而不是复制多个可变事实；记录的稳定背景若要入长期记忆，仍经 MEM 人工确认，不直接从事件级别推断。 |
| EVT-08 | 来源固定讨论 | 所有记录/要事可一键进入搭子并自动引用；按来源稳定 ID 首次建立关联会话，后续复用，跨天与内容更新不新建；当前引用用最新版本，历史保持原样，失败不能静默新建。 |
| EVT-09 | 四种要事与检查分离 | 长期/一次性 × 普通/高等级；纯经历可无时间；确认本次检查不自动结束要事，可明确安排下一次检查，旧记录与检查历史保留。 |

## 7. 验收标准

| 编号 | 场景 | 可检查结果 |
| --- | --- | --- |
| EVT-A01 | 图片保留 | 从含图记录生成要事，删原记录后图片仍显示；辅助编辑请求实际包含图片或明确能力错误。 |
| EVT-A02 | 普通与高等级 | 同一到期时间的两级事项，普通不触发 AI 建议，高等级触发；两者均保持待确认。 |
| EVT-A03 | 改期并发 | 复核进行中改期或编辑，旧请求不能回写覆盖；新时间到达后能重新检查。 |
| EVT-A04 | 用户确认 | 确认后关闭提醒；稍后确认保留历史；没有确认的事项不会因模型文本或任务状态自动完成。 |
| EVT-A05 | 建议有来源 | 相关任务尚无报告或条件不满足时明确指出缺口，不编造已做事实；模型失败可见且能重试。 |
| EVT-A06 | 固定讨论入口 | 首次点击自动引用；再次点击、双击/重试、跨天、改名/改正文后仍为同一 threadId；最新引用与旧历史同时保留；同名不同来源不串话题；映射加载失败不新增会话。 |
| EVT-A07 | 类型与检查 | 四种组合可保存；无时间的经历不提醒；确认一次不结束要事；长期再次约定后保留上次结果，旧检查回包不能覆盖新检查；A转B不共享threadId。 |

“已有测试通过”仅代表其覆盖的路径；模型请求能返回、页面能打开或接口 health 正常，不足以证明整个模块达标。

## 8. 依赖与后续边界

依赖 REC 图片快照和 SET 模型错误；关联证据增强需 ACT/SUP 的只读状态契约。普通/高等级与人工确认核心可先单独修复。

P2：系统推送、自动“人生传记”和复杂事件图谱；当前先把用户可见的情节记录与约定复核做好。

## 过滤与校验补充（2026-09-29）

遵守 [校验审查中的共同契约](../14-filter-validation-review.md)：候选、已选与可提交使用一致规则；无效已选项必须可见可移除；模型建议不等于有效业务数据。以下是目标约束，不代表代码已修复。

- **V01：** 模型返回值先校验对象结构、类型、长度、枚举及引用。标题/摘要/分类等业务内容超限不能无提示截断；无效必填字段显示具体原因。模型不能写 priority、confirmed、active、revision 等人工/服务端字段。关联建议可过滤去重，但必须返回被移除项的原因；用户已确认输入不能静默过滤。
- **V02：** 候选列表、已选列表和提交校验共用类型/空间/状态/自身排除规则；候选缺页不代表对象失效。已有选项即使不在当前页，也须显示摘要或失效占位及移除入口。提交时重新核验，失败保留草稿，按字段及具体 ID 返回原因。
- **V12：** 决定输入能力时检查实际附件及内容，不只按 note.type。请求记录实际读取的附件 ID/版本/数量，支持范围内的选定图片都纳入；超限或不支持时点名缺失部分并提供拆分，不能默默漏读。OCR/ASR 完成状态与上传状态分开。
- **V13：** 异步草稿绑定来源类型/ID/正文及附件版本和请求序号，返回时检查编辑会话仍匹配；不覆盖后来用户输入。独立图片先完整复制校验，再提交关联，失败清理临时副本但不删除原件；附件访问校验对象归属。
- **V14：** 同一 kind+id 自动引用应更新当前引用版本，不追加重复项。为保留五条上限，新增来源将超限时打开可见选择面板并指出必需来源，让用户替换可选项；不静默丢其他引用或另开会话。会话历史引用与当前待发送引用分开。
- **V16：** 复核有效性绑定实际输入依赖签名：要事相关字段、源记录/附件、实际读取的任务/证据版本及约定时间。提交与确认都回查依赖，旧建议保留历史但标过期，不阻碍不需复核的普通提醒；当前要事更新时间一个字段不够。
- **V17：** 编辑请求始终带当前 eventId，候选先排自身，建议去重/限10/回查存活，保存仍校验。已有失效关联可见可移除，不静默删用户选择。约定日期合法性服务端负责；Q06 已确认无提醒经历可不设时间，检查确认与要事结束分离；四种类型前后端校验一致，不自动重开已结束要事。

## Q05 已确认：记录与派生要事不共用会话

记录 A 生成要事 B 后，各自保持独立的固定搭子会话，不沿用、不合并。来源关系仍保留。2026-10-08补充确认：资料库文件也采用固定会话。首次从文件进入搭子时建立关联并引用文件；以后重复点击、刷新、跨天进入均恢复原会话。改名或更新正文不改变会话；不同文件按稳定来源ID区分，同名文件不合并。

## Q04 已确认：统一项目入口

用户已在对话中确认：点击 PersonalAgent，可以一起找到相关笔记、要事、项目文件及其他项目内容；不同来源的搭子会话各自保留，不合并。

共享 project 使用稳定 ID；项目类别显式关联 projectId，各模块按同一 ID 查询，不能用名称相同猜测关系。入口按内容类型分组且可分页，分别显示空/加载/失败，部分模块失败不能把整个项目说成无内容。旧项目字符串保留，映射不明确的先显示待关联，不静默合并同名项目；改名不改变 ID、引用或 threadId。聚合页面不等于把项目全量资料送入每次聊天，模型仍按问题、范围和预算读取。
