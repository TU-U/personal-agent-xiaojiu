# 搭子 plan

版本：2026-09-29 · 对应 [spec](<搭子spec.md>) · 本文件是后续开发清单，本次仅整理文档，未执行这些开发项。

## 1. 执行目标

在保留现有数据与可用能力的基础上，补齐 CHAT spec 的缺口。先 P0（正确性、状态与数据保护），再 P1（闭环与体验）；P2/需确认项不进入明日默认执行范围。以用户届时给出的 goal 范围为准，不能将本文自动理解为立即启动开发或创建 goal。

## 2. 前置核对与依赖

依赖 RET 来源契约和 MEM active/scope 读取规则；上下文分页可独立先做，再接 ACT/RES 草稿。旧消息与当前会话不依赖小九。

开始时核对当前代码和运行情况，读取本模块 spec 与总索引。09 是 V1 历史基线，10 是方案，11 是首轮实施记录；不得只按任一旧文档重新实现已有功能。本文中列出的“缺口”若已由用户或后续代码补好，记录现状并删去对应无效任务。

## 4. 数据兼容与失败处理

- 需要迁移时先保存一致性备份和 schema/version 信息；旧实体/引用/文件 ID 保持可解释，迁移可重入。只加兼容默认值，不伪造历史确认或完成状态。
- 先在隔离 DATA_DIR、临时来源目录和模型桩验证错误路径，不清空在线数据或用真实 E 盘做删除测试。
- 对外部服务不可用、缺密钥和人工确认等待，写明受影响的步骤及恢复条件；继续能独立完成的步骤。不能用假结果代替外部验收，也不能无限重试消耗模型。
- UI 保留输入并显示操作状态、失败原因和恢复入口；已有主题、Markdown 阅读和长内容滚动不因改动退化。

## 5. 最小验证集

选择 `tests/e2e/assistant-references.spec.ts` 与相关 API 测试；用确定性历史构造验证六轮边界和分页，模型模拟仅验证请求上下文，最后小样本人工核对，不批量制造真实会话。

涉及 TypeScript 时运行 `npm run check`；准备交付网页变更时运行一次 `npm run build`。浏览器仅选相关桌面测试，例如 `bash scripts/test-browser.sh <对应测试文件> --project=desktop`。不运行 mobile、android、native-bridge 或无关全套回归；已有通过结果可复用，只有新增改动/失败才重测相关部分。

将实际命令、结果、失败修复、剩余未验证项记入模块交付记录。spec 验收表中的案例要逐项有结果或明确依赖说明，不能仅写“测试通过”。

- 交付包含修改文件、数据变更、验证证据、使用入口和仍未达成的项；未完成项不得改为完成以结束 goal。
- 更新本模块实施状态或新增交付记录，不把目标 spec 改写为“已实现”来掩盖差距。

## 7. 本轮不自动执行

## Q04 实施补充：共享项目与聚合入口

与 REC 项目入口共用 projectId 和项目类别映射，提供本模块分组/分页查询，保留各来源固定会话。验收同项目内容可一起找到、同名不同项目不串、改名不丢关联、单组失败不冒充全空；旧字符串迁移只按明确关系，不推测合并。该工作不依赖待讨论的 ACT 新场景。

## Q09 实施补充：成功轮次与候选期限

为每个话题维护成功提交的轮次序号，消息幂等重试不加轮次；保存成功问答后统一驱动 MEM 候选期限检查，失败请求及其他话题不计。验收第五轮边界、旧页面确认竞争与清理后 PET 红点一致。


## Pi 接入追加计划：搭子按需联网（2026-10-08，Web/服务端已实施）

1. 为对话增加「允许联网」控制，按已确认规则绑定threadId在服务端持久保存，各会话独立，切换/刷新/跨天进入恢复对应会话的选择；请求绑定实际目标会话及相应许可，避免切换页面后误用其他会话设置。新建会话默认关闭联网，手动开启后持久保存；运行中关闭时更新会话许可，阻止后续联网工具派发并尽力取消在途搜索；保留已取得资料，继续完成当前回答。
2. 在pi-agent-core工具执行入口核验当前会话联网权限；关闭时禁止发起搜索和外部网页读取，不能仅隐藏按钮、依赖提示词或只读取任务启动时的旧许可。按会话/执行实例关联取消信号，尽力取消在途搜索；保留已取得资料及当前回答，本地检索与模型已有知识回答路径继续可用。
3. 开启后允许按需搜索并继续分析，展示真实进度、来源和失败状态；维持网页接力入口。正式研究任务仍进入计划确认，不被聊天工具循环绕过。
4. 接入已确认的每次回答6次模型调用/2分钟/1元预算，重试计入同一额度；任一触顶停止追加调用并展示已有结果及继续入口。最小验证包括开关关闭时模型请求搜索也不能执行、开启时按需搜索并返回来源、搜索失败如实显示，以及转入正式调研仍要求计划确认；定向检查新建会话默认关闭，以及A/B会话设置独立且重新打开仍保留。补受控在途场景：搜索中关闭后无新联网调用、已有资料仍可回答、取消失败不虚报成功，且不影响其他会话。只做受影响的定向验收。

后续已获实施授权并完成 Web/服务端接入，依赖锁定 Pi 1.1.0；当前实现与验证见 [27号实施记录](../27-pi-agent-implementation.md)。


## Q05 追加：资料库文件固定会话（2026-10-08，已确认）

- 将资料库文件明确纳入既有来源会话契约，与记录、要事共用按用户空间/来源类型/稳定ID定位的映射服务；保留已有可靠关联，不另建第二套映射或覆盖历史。
- 第一次从文件进入搭子时引用该文件并建立会话；再次进入、跨天、改名或正文更新均复用同一会话。读取最新已保存文件版本作为本轮引用，历史引用版本保留。
- 不按文件名或内容相似度合并不同资料库实体，不因来源读取失败自动创建新会话；文件删除按既有失效引用规则保留独立讨论历史。
- 实施时先核对现有资料库入口与source-thread实现，复用已有网页链路证据，仅补缺失的改名/正文更新与同名不同ID边界；不要为了确认需求重写已经可用的路径。


## Pi 接入追加计划：预算执行（2026-10-08，Web/服务端已实施）

1. 在单次回答执行实例中保存调用计数、执行起始/截止时间、已结算与预留费用；关联request/thread及恢复状态，复用项目已有预算与计价能力，避免建立彼此矛盾的计费逻辑。
2. 所有模型派发、工具后的续答及重试共用6次/2分钟/1元限制；派发前核验、请求预留与输出限制、返回后结算。不能仅等模型返回后才发现已超预算。
3. 到达任一限制时停止追加执行，尽力取消在途操作，展示已取得结果及停止原因；继续由用户主动追加额度，保留累计使用记录。
4. 使用受控模型、可控时钟与固定价格做少量边界验证：三类上限分别触发、重试不重置、未知计价不冒充免费、重复继续不重复启动。只做定向验证，不用大量真实付费调用验证限制。
