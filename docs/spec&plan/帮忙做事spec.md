## 1. 目标与模块责任

把讨论中的目标转成可确认的计划，通过受限工具逐步推进，留下可恢复的状态、真实执行记录和可检查的产物。

## 2. 当前实现与缺口

### 已有基础

`server/work-tasks.mjs` 已实现 workTask 计划生成、确认启动、最多 8 次工具/约 10 分钟、2 次自动重试、暂停/继续/取消、waiting 和 review 状态；`server/task-tools.mjs` 有副本读取、公开网页读取、写 Markdown 文件。重启把 running 任务置为 paused。旧 `task` 实体仍用于成果生成，不是 workTask。

### 需要补齐

目前 runner 主要是 JSON 动作选择循环；plan.steps 是字符串，没有持久步骤对象和工具幂等账本。产物先写实体再写文件/关联，失败可能产生孤立实体或重复产物；创建/操作缺跨请求幂等。保留产出步骤只判断是否曾有 output，旧产物可能影响新一轮收束；计划修订、取消终态、断网重试和跨重启恢复需加强。

## 3. 范围与非目标

现有框架草案中的工具只查资料、读公开网页、按已授权规则复制资料到项目内、记录进度、生成或更新项目内成果。不提供任意 shell、桌面代操作、自动发布、发送消息、登录网站或支付。需要这些动作时交付方案并标明未执行。

## 4. 用户流程

话题/资料/研究结果 → 任务草稿 → 用户检查并可修改计划与条件 → 确认计划版本 → 执行一个受控步骤 → 持久保存结果 → 下一步或等待输入 → 交阶段产物 → 用户检查；现实完成交给督促模块验收。
暂停阻止派发新工具，允许正在提交的原子步骤收尾；继续读取持久状态。取消是终态，不能被迟到回调重新设成运行。

## 5. 数据与状态契约

保留 workTask；目标扩展 planRevision、confirmedPlanRevision、project、referenceIds、stepIds、runId、budget、blockedReason、nextAction。新增/扩展 workStep 与 toolInvocation，记录 operationId、inputHash、status、startedAt、resultRef、error、attempt。
状态建议：draft → running → paused/waiting/failed/review；cancelled 为终态。不要把 review 改名 completed 来混淆现实执行。产物关联 artifactId + taskId + runId + stepId；不要和旧 artifact-generation `task` 共用同一个状态模型。

本节新增字段是目标契约，不是已落地 schema。实现时优先兼容既有实体，迁移前备份，禁止为了符合新字段丢弃历史数据。

## 6. 功能与异常要求

| 编号 | 要求 | 具体行为 |
| --- | --- | --- |
| ACT-01 | 计划确认 | 展示目标、条件、步骤、产物、限制；计划修改生成新版本，影响范围或完成条件时重新确认。已有授权范围内的每个只读工具不重复询问用户。 |
| ACT-02 | 受控执行 | 工具必须有输入校验、作用域、超时和结构化结果；不能仅凭 prompt 承担文件边界。资料和网页内容不能扩大工具权限。读取大文件可按段继续并显示截断。 |
| ACT-03 | 持久状态 | 步骤开始、完成、失败、等待原因及下一步写库；执行记录能解释实际做了什么。进程崩溃后辨识已提交副作用，不盲目重放。 |
| ACT-04 | 预算与收束 | 默认 8 次工具、10 分钟、最多 2 次自动重试；剩余预算以本轮为准，预留产出步骤。失败按类型重试；重复无效搜索停止并说明缺口。 |
| ACT-05 | 幂等与一致性 | 双击、网络重试、定时重复触发、重启不能重复复制或生成同一产物。文件与数据库关联失败可恢复；已有产物更新保留版本。 |
| ACT-06 | 交付真实性 | 报告带来源、实际动作、未执行事项和待验证结论。工具成功只代表对应动作成功，不能代替用户确认学习或现实任务完成。 |
| ACT-07 | 控制和衔接 | 支持计划编辑、启动、暂停、继续、取消、查看失败、补充外部结果、打开/下载成果。取消不删除已有证据；用户手工修改产物不能被后台覆盖。 |

## 7. 验收标准

| 编号 | 场景 | 可检查结果 |
| --- | --- | --- |
| ACT-A01 | 真实任务 | 从话题建立计划，确认后串联检索→读取→产物，来源、步骤和文件可回看；没有确认不能启动。 |
| ACT-A02 | 副作用幂等 | 重复提交 start/继续/产物写入或模拟响应丢失，只有一个对应 step/产物版本。 |
| ACT-A03 | 故障恢复 | 分别在工具前、文件已落盘但关联未提交、提交成功响应前模拟中断；重启后可恢复且不重复副作用。 |
| ACT-A04 | 暂停与取消 | 耗时工具期间暂停/取消，迟到返回不启动下一步、不复活取消任务；已完成文件仍可查看。 |
| ACT-A05 | 预算控制 | 模型持续搜索或返回非法工具时达到上限并保存进度；已有上轮产物不掩盖本轮没有新交付。 |
| ACT-A06 | 越界动作 | 请求写 E 盘、任意 shell、发布内容或未授权网络动作被拒绝并记录；正常只读工具不反复弹确认。 |

“已有测试通过”仅代表其覆盖的路径；模型请求能返回、页面能打开或接口 health 正常，不足以证明整个模块达标。

## 8. 依赖与后续边界

依赖 SET 的数据备份/日志和 RET 的读取边界；先稳定状态/幂等，再让 RES、SUP 消费同一 workTask。REC 统一产物正文与文件版本。

P2：任意代码执行、浏览器代操作和对外发布不在明日默认范围。自主定时重启执行需另设明确任务授权，当前重启暂停策略保留。

## 过滤与校验补充（2026-09-29）

遵守 [校验审查中的共同契约](../14-filter-validation-review.md)：候选、已选与可提交使用一致规则；无效已选项必须可见可移除；模型建议不等于有效业务数据。以下是目标约束，不代表代码已修复。

本模块仍待讨论，本补充不构成启动开发授权。

- **V01：** 模型返回值先校验对象结构、类型、长度、枚举及引用。标题/摘要/分类等业务内容超限不能无提示截断；无效必填字段显示具体原因。模型不能写 priority、confirmed、active、revision 等人工/服务端字段。关联建议可过滤去重，但必须返回被移除项的原因；用户已确认输入不能静默过滤。
- **V02：** 候选列表、已选列表和提交校验共用类型/空间/状态/自身排除规则；候选缺页不代表对象失效。已有选项即使不在当前页，也须显示摘要或失效占位及移除入口。提交时重新核验，失败保留草稿，按字段及具体 ID 返回原因。
- **V08：** 未来确认场景后，工具 allowlist、参数 schema、资源归属、计划版本和运行状态均在服务端派发及提交时核验；幂等键绑定执行实例/步骤及输入。同键不同输入报冲突，取消/暂停边界按共享契约。不得因本条启动 ACT 新功能。


## 最新方向：技能工作台 Skill Studio（2026-10-08，待实施）

用户明确要求：编辑与调试放在独立页面，不将全部开发功能堆入日常拾光界面。用户澄清 `/dev` 只是路径示例，并未指定名称；本方案命名为「技能工作台（Skill Studio）」，路径采用 `/studio`，可手动输入地址进入。此条覆盖上一版“只在外部开发环境调试”的安排。

### 已明确的界面职责

- 日常主界面：选择可用skill、填写任务材料与参数、执行并查看进度和结果；保留搭子推荐后由用户确认运行的入口。
- `/studio`：集中承载skill编辑与调试，支持围绕skill检查内容、修改、试运行和查看调试信息；具体首版编辑文件范围与运行能力仍待确认。
- 通过手动输入 `/studio` 进入，不在日常导航增加一组开发工具；外部开发工具仍可用于准备skill，不强制所有修改都在网页完成。
- `/studio` 是同一应用里的独立工作台页面，不是Vite开发服务器地址，也不自动意味着拆成独立部署项目。

### 待确认的实施边界

- 导入格式、附带脚本/模板/依赖，以及编辑器首版支持哪些文件。
- 历史版本保留、更新回退和停用等细节；草稿与正式启用关系已按下节确认。
- 工具、文件、网络操作范围与依赖运行环境；目录/页面分离不自动获得新的执行权限。
- 执行日志、结果预览、更新回退及失败恢复的首版范围，首个可复现验收skill。

Pi仍随拾光集成和升级；通用插件安装系统不因新增 `/studio` 自动纳入。沿用不直接管理E盘原件的约束。编辑/调试操作使用现有身份认证及服务端校验，不能把路径隐蔽性作为权限控制。仅使用pi-ai + pi-agent-core并不等于已接入技能加载器，具体方案另行设计。

参考：[Pi官方Skills文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/skills.md)。

### 调用入口已确认（2026-10-08，待实施）

### 草稿与版本启用已确认（2026-10-08，待实施）

- 工作台保存修改只更新草稿；允许使用草稿进行试运行，修改和试运行不自动改变日常调用版本。
- 用户点击「启用此版本」后，主界面的后续调用才使用新版；启用前继续使用原来的已启用版本。没有已启用版本的skill不能作为正式可调用项。
- 实现约定：启用产生明确版本快照，后续草稿编辑不修改该快照；执行实例记录并固定实际使用的版本，避免执行中途因编辑或启用另一版本切换脚本。
- 版本隔离与执行环境是两个问题；草稿试运行的工具、文件和网络范围仍按后续确认的规则执行，不把“草稿”标识当成无副作用保证。
