## 4. 数据兼容与失败处理

- 需要迁移时先保存一致性备份和 schema/version 信息；旧实体/引用/文件 ID 保持可解释，迁移可重入。只加兼容默认值，不伪造历史确认或完成状态。
- 先在隔离 DATA_DIR、临时来源目录和模型桩验证错误路径，不清空在线数据或用真实 E 盘做删除测试。
- 对外部服务不可用、缺密钥和人工确认等待，写明受影响的步骤及恢复条件；继续能独立完成的步骤。不能用假结果代替外部验收，也不能无限重试消耗模型。
- UI 保留输入并显示操作状态、失败原因和恢复入口；已有主题、Markdown 阅读和长内容滚动不因改动退化。

## 5. 最小验证集

涉及 TypeScript 时运行 `npm run check`；准备交付网页变更时运行一次 `npm run build`。浏览器仅选相关桌面测试，例如 `bash scripts/test-browser.sh <对应测试文件> --project=desktop`。不运行 mobile、android、native-bridge 或无关全套回归；已有通过结果可复用，只有新增改动/失败才重测相关部分。

将实际命令、结果、失败修复、剩余未验证项记入模块交付记录。spec 验收表中的案例要逐项有结果或明确依赖说明，不能仅写“测试通过”。
