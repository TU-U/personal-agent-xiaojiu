# 要事 plan

版本：2026-09-29 · 对应 [spec](<要事spec.md>) · 本文件是后续开发清单，本次仅整理文档，未执行这些开发项。

## 1. 执行目标

在保留现有数据与可用能力的基础上，补齐 EVT spec 的缺口。先 P0（正确性、状态与数据保护），再 P1（闭环与体验）；P2/需确认项不进入明日默认执行范围。以用户届时给出的 goal 范围为准，不能将本文自动理解为立即启动开发或创建 goal。

## 2. 前置核对与依赖

依赖 REC 图片快照和 SET 模型错误；关联证据增强需 ACT/SUP 的只读状态契约。普通/高等级与人工确认核心可先单独修复。

开始时核对当前代码和运行情况，读取本模块 spec 与总索引。09 是 V1 历史基线，10 是方案，11 是首轮实施记录；不得只按任一旧文档重新实现已有功能。本文中列出的“缺口”若已由用户或后续代码补好，记录现状并删去对应无效任务。

## 3. 分步实施

### EVT-P01 · P0 · 梳理复核和确认状态

- 对应需求：EVT-03, EVT-04, EVT-05, EVT-06。
- 工作：审计 dueAt/reviewedDueAt/revision 的原子检查；给复核请求绑定事件和计划快照。补确认/改期记录，普通等级不调用复核。
- 代码入口：server/events.mjs；server/index.mjs；server/store.mjs。
- 完成证据：EVT-A02、A03、A04；不改既有等级语义。
- 顺序：先满足本步骤引用的数据/接口依赖；已满足的部分记录证据并跳过，不能为打勾重复开发。

### EVT-P02 · P1 · 关联证据与建议

- 对应需求：EVT-04, EVT-07。
- 工作：接 ACT/SUP/REC 的引用读取，限制复核上下文并显示来源；只有相关证据存在才判断，不把整库记忆塞入 prompt。
- 代码入口：server/events.mjs；server/engine.mjs；src/types.ts。
- 完成证据：EVT-A05；来源过期时说明，不能直接写计划已完成。
- 顺序：先满足本步骤引用的数据/接口依赖；已满足的部分记录证据并跳过，不能为打勾重复开发。

### EVT-P03 · P1 · 要事编辑与回顾

- 对应需求：EVT-01, EVT-02, EVT-05。
- 工作：完善 AI 草稿/手动保存、相关建议布局、图片快照、经历日期和稍后确认选择。旧事件 occurredAt 为空而非编造发生时间。
- 代码入口：src/Events.tsx；server/index.mjs；src/styles.css。
- 完成证据：EVT-A01、A04；桌面只验关键滚动和时间选择。
- 顺序：先满足本步骤引用的数据/接口依赖；已满足的部分记录证据并跳过，不能为打勾重复开发。

### EVT-P04 · P1 · 来源一键进入固定搭子会话

- 对应需求：EVT-08；共同契约：CHAT-08。
- 工作：在所有要事的查看入口提供“与搭子讨论”，调用 CHAT-P05 的统一关联接口并打开返回的 threadId，自动携带来源引用；不自行生成新 threadId。改名、正文更新和跨天仍复用原会话，当前引用读取最新保存版本；保留旧讨论。按钮显示加载/错误并支持重试，不因失败新建。
- 依赖：CHAT 负责映射和会话恢复，REC / EVT 负责来源入口与当前版本读取；不依赖待讨论的 ACT 新场景。
- 完成证据：EVT-A06；桌面核对记录和要事入口、自动引用、编辑后再次进入；用必要的接口测试覆盖并发首次点击唯一性与失败不新建。复用现有引用测试，不扩大到无关全套回归。

### EVT-P05 · P0 · 四种要事与独立检查实例

- 对应 EVT-09 / EVT-A07。迁移新增 eventType、生命周期和检查实例，保留旧 ID、图片、来源会话与复核历史；旧数据无法确定长期/一次性时标注待选择，不擅自猜类型或完成状态。
- 移除“只因高等级就必须有提醒时间”的前后端规则；检查时间只约束启用的检查。明确“确认本次检查”“安排下一次”“结束要事”三个不同动作。
- 模型不能改类型/等级/确认状态；小九按检查实例去重，旧 dueAt/reviewedDueAt 兼容迁移不改变用户事实。固定讨论不沿用来源记录线程。

## 4. 数据兼容与失败处理

- 需要迁移时先保存一致性备份和 schema/version 信息；旧实体/引用/文件 ID 保持可解释，迁移可重入。只加兼容默认值，不伪造历史确认或完成状态。
- 先在隔离 DATA_DIR、临时来源目录和模型桩验证错误路径，不清空在线数据或用真实 E 盘做删除测试。
- 对外部服务不可用、缺密钥和人工确认等待，写明受影响的步骤及恢复条件；继续能独立完成的步骤。不能用假结果代替外部验收，也不能无限重试消耗模型。
- UI 保留输入并显示操作状态、失败原因和恢复入口；已有主题、Markdown 阅读和长内容滚动不因改动退化。

## 5. 最小验证集

复用 `tests/e2e/events.spec.ts` 和 API 的要事/图片/到期复核用例。定时测试使用指定时钟，重点看等级、人工确认与改期竞态。

涉及 TypeScript 时运行 `npm run check`；准备交付网页变更时运行一次 `npm run build`。浏览器仅选相关桌面测试，例如 `bash scripts/test-browser.sh <对应测试文件> --project=desktop`。不运行 mobile、android、native-bridge 或无关全套回归；已有通过结果可复用，只有新增改动/失败才重测相关部分。

将实际命令、结果、失败修复、剩余未验证项记入模块交付记录。spec 验收表中的案例要逐项有结果或明确依赖说明，不能仅写“测试通过”。

## 6. 完成判定与交付

- 选定的 P0/P1 需求及对应 spec 验收达成；只完成页面入口或一次模型请求不能关闭模块。
- 数据兼容、错误提示和跨模块引用已验证，未动 E 盘原件与手机工程。
- 交付包含修改文件、数据变更、验证证据、使用入口和仍未达成的项；未完成项不得改为完成以结束 goal。
- 更新本模块实施状态或新增交付记录，不把目标 spec 改写为“已实现”来掩盖差距。

## 7. 本轮不自动执行

P2：系统推送、自动“人生传记”和复杂事件图谱；当前先把用户可见的情节记录与约定复核做好。

## 过滤与校验实施门槛（2026-09-29）

- **V01 完成证据：** 模型返回 null、错类型、超长正文、非法枚举和越权字段：无副作用，错误可定位；合法响应可直接进入相同保存校验。
- **V02 完成证据：** 选中后翻页、删对象、切换类型：仍可看见与移除旧选项；合法选择提交成功，无隐藏阻塞项。
- **V12 完成证据：** 文字+图、多图、纯图和不支持附件：实际模型输入与界面声称读取的范围完全一致。
- **V13 完成证据：** 辅助编辑期间更换来源或手改正文不被覆盖；第二张复制失败时旧图和记录不丢；下载对应当前保存版本。
- **V14 完成证据：** 已有5条时重进同来源仍5条；进入新来源时能看清并解决超限；原threadId和历史不变。

## Q04 实施补充：共享项目与聚合入口

与 REC 项目入口共用 projectId 和项目类别映射，提供本模块分组/分页查询，保留各来源固定会话。验收同项目内容可一起找到、同名不同项目不串、改名不丢关联、单组失败不冒充全空；旧字符串迁移只按明确关系，不推测合并。该工作不依赖待讨论的 ACT 新场景。
