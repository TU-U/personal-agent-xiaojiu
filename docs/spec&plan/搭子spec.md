# 搭子 spec

版本：2026-09-29 · 模块编号：CHAT · 范围：网页端与服务端。

本文区分现状与目标；“必须”描述待验收规范，不代表代码已全部做到。与 [实施计划](<搭子plan.md>) 配套，跨模块规则见 [总索引](README.md)。来源为 [V1 基线](../09-v1-overview.md)、[第二阶段方案](../10-phase2-product-plan.md)、[首轮实施记录](../11-phase2-implementation.md) 与本次代码核对。新设计细节是本次整理的实现目标；未来扩展不能被自动执行器当作已获授权。

## 1. 目标与模块责任

作为生活化讨论、随笔记录、项目 idea 和轻量头脑风暴伙伴，围绕一个话题持续分析；需要时带着已有资料转为研究、任务或要事。

## 2. 当前实现与缺口

### 已有基础

已有按 threadId 分话题、跨天继续、最近六轮上下文、记录/要事引用和资料库引用入口、来源展示、搜索简报、每轮记忆候选以及创建任务。`thread-context.mjs` 对六轮以前的内容生成滚动摘要；完整消息仍在库里。bootstrap 只返回最近 200 条 conversation。

### 需要补齐

长话题显示和历史分页不足；摘要按批次异步推进，落后时不能保证历史覆盖，提示词中的回答又被截到 500 字。手选来源截前 3,000 字可能丢引用长文的关键段落。资料库来源引用和旧话题重开、摘要失败/过期、scope 记忆选择还需贯通。

## 3. 范围与非目标

优先自然讨论与分析，保留已有能力，不重做大型“搭子人格系统”。本次搭子完善主要服务上下文可靠性和其他模块衔接。小九轻聊天独立，不读取小九会话；不把所有话题并成一个无限聊天上下文。

## 4. 用户流程

新建/打开某话题 → 可选引用记录、要事、资料 → 提问 → 读取该话题近期轮次+摘要+相关生效记忆+本轮来源 → 回答并展示依据 → 用户接着讨论。
新主题新建会话，跨天仍可继续旧主题。需要研究、执行或要事时先给草稿或候选，再交用户确认。

### 已确认：从来源回到固定讨论（2026-09-29）

所有记录、要事和资料库文件提供“与搭子讨论”入口，点击即跳转搭子并自动引用该来源。第一次为该来源建立关联会话；以后重复点击、刷新或跨天进入，都回到同一会话，延续历史与上下文，不重复新建。修改标题或正文不改变关联会话；本次引用读取最新已保存版本，历史消息及其当时的引用版本保留，不用新内容篡改过去的讨论。

- 关联依据是当前用户空间内的来源类型与稳定 ID，不按标题、正文哈希、日期或 revision 新建会话。同名不同记录不能混入同一上下文。
- CHAT 维护持久的来源 → threadId 映射，REC / EVT / 资料库入口只调用同一个“获取或建立关联会话”入口。唯一约束和事务保证双击、重试及并发访问只建立一个关联；加载失败应报错重试，不能用新建会话掩盖失败。
- 已有关联时优先恢复原会话并去重更新该来源的当前引用；点击本身不发送用户消息、不自动调用模型。会话近期消息、摘要与上下文预算沿用 CHAT 规则，延续不等于每次无限载入完整原文。
- 不把其他话题中偶然引用过该来源的会话全部合并；旧数据已有明确关联则沿用，没有可靠关联时只在首次入口操作建立映射，不按相同标题猜测历史关系。普通按话题新建会话的能力保留，不改变来源入口的固定去向。
- 来源或关联会话不可用时保留映射与历史并显示原因，不静默新建或改绑。删除来源不级联删除独立讨论历史，来源引用按失效规则显示。

以上是目标契约，尚不代表入口与映射已实现；“同一来源”指同一记录 / 要事 / 资料库文件实体（资料库文件于2026-10-08补充确认），不按文件名跨实体自动合并。

## 5. 数据与状态契约

新增持久来源关联 sourceThreadLink（用户空间、sourceKind、sourceId、threadId），对用户空间 + sourceKind + sourceId 建唯一约束；revision 只描述引用版本，不参与关联键。
沿用 conversation、threadId/threadTitle、references、sources、memoryProposals。扩展线程目录与分页接口，不依赖 bootstrap 最近 200 条推导全部话题。
threadSummary 保存 covered message ids/revisions 或内容签名、版本、更新时间、失效原因与未覆盖范围；query/body 原文不被摘要覆盖。上下文组装记录使用了哪些轮次、摘要和记忆，控制 token 预算。

本节新增字段是目标契约，不是已落地 schema。实现时优先兼容既有实体，迁移前备份，禁止为了符合新字段丢弃历史数据。

## 6. 功能与异常要求

| 编号 | 要求 | 具体行为 |
| --- | --- | --- |
| CHAT-01 | 分话题延续 | 同一话题可跨天继续，话题之间不混入原始对话；共享长期记忆只通过 MEM 的生效与适用范围选择。能找到和打开旧话题完整历史。 |
| CHAT-02 | 上下文覆盖 | 近期对话和摘要覆盖较早内容，摘要落后/失败可见，关键用户约束不能因超过六轮静默消失。预算压缩优先去冗余，不随意把助手推测写成用户事实。 |
| CHAT-03 | 引用与定位 | 用户可引用记录/要事/资料；明确本轮所读片段、位置与版本，长文按相关段落读取而不是永远只看开头。已删除来源提示移除/换用快照，不静默换成别的资料。 |
| CHAT-04 | 判断而非伪事实 | 回答区分事实、推断、未知和下一步；来源支撑具体判断。没模型时明确为本地摘录；空返回、模型错误和检索异常有报错入口。 |
| CHAT-05 | 联网衔接 | 应用内检索与网页接力沿用 RES 协议；生成可编辑背景/问题/固定答复格式，用户带回结果后保留外部来源和时效。 |
| CHAT-06 | 转行动和记忆 | 从当前话题生成研究/行动草稿，不丢背景与引用；要事由用户定等级和时间。每轮只提稳定事实候选，用户选择前不能更新长期记忆。 |
| CHAT-07 | 体验与失败恢复 | 输入保留、发送状态明确，重复发送不制造双轮；来源、长回答、记忆选择和话题列表可滚动，复选框与标签不被撑成整行。 |
| CHAT-08 | 来源固定讨论 | 所有记录/要事可一键进入搭子并自动引用；按来源稳定 ID 首次建立关联会话，后续复用，跨天与内容更新不新建；当前引用用最新版本，历史保持原样，失败不能静默新建。 |

## 7. 验收标准

| 编号 | 场景 | 可检查结果 |
| --- | --- | --- |
| CHAT-A01 | 跨天专注 | 两个不同话题各继续一次，代词能接对本话题，不能串入另一话题原文。 |
| CHAT-A02 | 长上下文 | 超过六轮且历史超出 bootstrap 窗口仍能找到早先约束；摘要失败或积压会显示并采用明确补偿策略。 |
| CHAT-A03 | 长文引用 | 选择关键内容在后半部分的资料提问，回答依据是相关段落并可回看版本。 |
| CHAT-A04 | 转任务不丢背景 | 创建任务的草稿包含用户目标、引用和已确认条件；不会自动跑外部动作或写 active 记忆。 |
| CHAT-A05 | 失败可恢复 | 空模型、失效引用、网络重试不吞用户输入、不伪装成功、不多存一轮。 |
| CHAT-A06 | 固定讨论入口 | 首次点击自动引用；再次点击、双击/重试、跨天、改名/改正文后仍为同一 threadId；最新引用与旧历史同时保留；同名不同来源不串话题；映射加载失败不新增会话。 |

“已有测试通过”仅代表其覆盖的路径；模型请求能返回、页面能打开或接口 health 正常，不足以证明整个模块达标。

## 8. 依赖与后续边界

依赖 RET 来源契约和 MEM active/scope 读取规则；上下文分页可独立先做，再接 ACT/RES 草稿。旧消息与当前会话不依赖小九。

P2：人格、长期情感关系、多 Agent 聊天、语音通话。此前“搭子先不管”的范围优先解释为不扩展陪伴产品，只修已落地的上下文与关联可靠性。

## 过滤与校验补充（2026-09-29）

遵守 [校验审查中的共同契约](../14-filter-validation-review.md)：候选、已选与可提交使用一致规则；无效已选项必须可见可移除；模型建议不等于有效业务数据。以下是目标约束，不代表代码已修复。

- **V01：** 模型返回值先校验对象结构、类型、长度、枚举及引用。标题/摘要/分类等业务内容超限不能无提示截断；无效必填字段显示具体原因。模型不能写 priority、confirmed、active、revision 等人工/服务端字段。关联建议可过滤去重，但必须返回被移除项的原因；用户已确认输入不能静默过滤。
- **V02：** 候选列表、已选列表和提交校验共用类型/空间/状态/自身排除规则；候选缺页不代表对象失效。已有选项即使不在当前页，也须显示摘要或失效占位及移除入口。提交时重新核验，失败保留草稿，按字段及具体 ID 返回原因。
- **V14：** 同一 kind+id 自动引用应更新当前引用版本，不追加重复项。为保留五条上限，新增来源将超限时打开可见选择面板并指出必需来源，让用户替换可选项；不静默丢其他引用或另开会话。会话历史引用与当前待发送引用分开。
- **V15：** 发送时固定 threadId、请求幂等键及来源版本，不从回调时活动页面重取目标。摘要携带覆盖签名及引用版本，重建采用版本比较，当前引用和历史快照明确分开；选项变动不改写已发送消息。

## Q05 已确认：记录与派生要事不共用会话

记录 A 生成要事 B 后，各自保持独立的固定搭子会话，不沿用、不合并。来源关系仍保留。2026-10-08补充确认：资料库文件也采用固定会话。首次从文件进入搭子时建立关联并引用文件；以后重复点击、刷新、跨天进入均恢复原会话。改名或更新正文不改变会话；不同文件按稳定来源ID区分，同名文件不合并。

## Q04 已确认：统一项目入口

用户已在对话中确认：点击 PersonalAgent，可以一起找到相关笔记、要事、项目文件及其他项目内容；不同来源的搭子会话各自保留，不合并。

共享 project 使用稳定 ID；项目类别显式关联 projectId，各模块按同一 ID 查询，不能用名称相同猜测关系。入口按内容类型分组且可分页，分别显示空/加载/失败，部分模块失败不能把整个项目说成无内容。旧项目字符串保留，映射不明确的先显示待关联，不静默合并同名项目；改名不改变 ID、引用或 threadId。聚合页面不等于把项目全量资料送入每次聊天，模型仍按问题、范围和预算读取。


## Pi 接入追加：允许联网开关（2026-10-08，已确认，待实施）

- 对话提供「允许联网」开关；开启后，搭子可按需要自行搜索，无需每次搜索前询问用户。搜索中显示进度，回答附来源。
- 关闭后不发起新的联网搜索或外部网页读取，使用本地记录、有效记忆与模型已有知识回答；缺少最新信息时明确说明。此开关控制搜索取材，不代表云端对话模型离线运行。
- 正式转入快速学习/调研时仍先确认计划，不因开启联网绕过RES的确认和预算规则；现有网页接力入口保留。
- **保存范围已确认（2026-10-08）**：联网开关按会话独立持久保存，各话题使用各自的设置；跨天重新进入同一会话时恢复上次选择。
- **新会话默认值已确认（2026-10-08）**：新建会话默认关闭联网；用户手动开启后保存该会话的选择。
- **运行中关闭联网已确认（2026-10-08）**：立即停止发起新的搜索和外部网页读取，尽量取消已经进行中的搜索；已取得的资料保留，继续用于完成回答。关闭联网本身不取消整轮回答，不删除已有引用。
- 实现约定：后端工具派发前重新核验当前会话许可；取消请求不等于已经完成取消，无法取消的在途请求不得继续派生新的联网取材。界面如实显示已停止后续搜索及取消结果，不能伪称所有外部请求已撤回。关闭不影响其他会话的独立选择。
- 搭子每次回答受已确认的6次模型调用、2分钟、1元预算限制，具体口径见下节；开启联网不代表无限调用授权。
- 搜索工具的许可必须在后端执行入口核验，不能只靠提示词让模型自觉遵守；前端需如实区分搜索结果、搜索失败和模型已有知识。


## Pi 接入追加：搭子循环预算（2026-10-08，已确认，待实施）

- 一次用户提问对应的一次回答，最多6次模型调用、总执行时间2分钟、费用预算1元人民币；达到任一上限即停止追加调用，展示已取得结果与尚未完成的部分，由用户决定是否继续。
- 自动重试和工具结果后的模型续答计入同一预算；不能通过重试、换模型或换搜索路径重置计数。6次指模型调用，不是6条用户聊天消息。
- 时间包含本次执行中的检索、模型、工具与重试等待；达到时限停止新增调用并尽力取消在途操作，保留已取得资料和结果，不能伪称已完成。
- 费用实施口径：根据实际供应商定价记录模型及付费工具消耗，派发前检查已用/预留额度并限制下一次请求，返回后按用量结算。计价缺失或过期时明确提示不能核算，不能把未知费用记成零或宣称预算已受控；取消不代表供应商已发生的费用被撤销。
- 用户选择继续时明确展示要追加的执行额度，经主动操作后续行；累计消耗与此前结果保留，不能自动重置后无限运行。
- 正式快速学习/调研继续采用既有先确认计划、5分钟/1元预算，不因搭子限制而被替换。
