在保留现有数据与可用能力的基础上，补齐 RES spec 的缺口。先 P0（正确性、状态与数据保护），再 P1（闭环与体验）；P2/需确认项不进入明日默认执行范围。以用户届时给出的 goal 范围为准，不能将本文自动理解为立即启动开发或创建 goal。

## 2. 前置核对与依赖

依赖 RET 的来源检索、ACT 的持久执行器、REC 的成果；按本模块范围补共享执行器必要能力和来源契约，不等待整套待讨论的 ACT-P0。向 EVT/SUP 输出候选或任务引用，不直接确认。

开始时核对当前代码和运行情况，读取本模块 spec 与总索引。09 是 V1 历史基线，10 是方案，11 是首轮实施记录；不得只按任一旧文档重新实现已有功能。本文中列出的“缺口”若已由用户或后续代码补好，记录现状并删去对应无效任务。

## 3. 分步实施

### RES-P01 · P0 · 证据记录标准化

- 对应需求：RES-04, RES-08。
- 工作：把 tool result 转为结构化 source/evidence；全文、摘要、回填有明确标记。read_web 的长度截断可见，长文本按位置继续读取。给关键结论引用加可核对证据检查；区分模型已有知识与实际证据，记录 researchMode、fallbackReason 及逐结论核验状态，不为模型知识伪造 URL 或获取时间。
- 代码入口：server/task-tools.mjs；server/web-search.mjs；server/engine.mjs；src/components.tsx。
- 完成证据：RES-A02、A04；URL 可打开不等于内容已验证。
- 顺序：先满足本步骤引用的数据/接口依赖；已满足的部分记录证据并跳过，不能为打勾重复开发。

### RES-P02 · P1 · 研究简报与模板

- 对应需求：RES-01, RES-02, RES-05。
- 工作：在已有任务创建表单增加研究类型、问题清单、输出模板和时间口径；任务执行协议由 ACT 模块统一，不复制 runner。
- 代码入口：src/WorkTasks.tsx；src/Assistant.tsx；server/work-tasks.mjs。
- 完成证据：RES-A01；任务草稿兼容无 researchBrief 的旧数据。
- 顺序：先满足本步骤引用的数据/接口依赖；已满足的部分记录证据并跳过，不能为打勾重复开发。

### RES-P03 · P1 · 联网失败降级、搜索简报与回填

- 对应需求：RES-03, RES-08。
- 工作：在共享执行器中捕获联网超时、限流、配置缺失及读取失败，保留已获取证据，自动以已有研究简报、引用与资料调用生成模型 API，使用已有知识继续；提示词与输出契约禁止冒充联网核验。降级不默认切换 waiting，采用 RES-09 的5分钟/1元预算，复用共享执行器取消与幂等语义。界面和报告展示简短失败原因、降级标签、待核实项，以及可选的重试联网/网页搜索入口；生成 API 也失败则报错并保留进度。复用 search-brief 逻辑，任务和搭子共用可编辑格式、复制反馈、原始链接及回填入口；只有用户选择网页接力才等待回填；回填不自动变成可信证据或长期记忆。重试联网/回填后更新同一任务和报告版本，不重复创建。
- 代码入口：server/search-brief.mjs；server/web-search.mjs；server/task-tools.mjs；server/work-tasks.mjs；src/Assistant.tsx；src/WorkTasks.tsx。
- 完成证据：RES-A03、RES-A06、RES-A07；不真实发送无关隐私资料给搜索服务。
- 顺序：先满足本步骤引用的数据/接口依赖；已满足的部分记录证据并跳过，不能为打勾重复开发。

### RES-P04 · P1 · 覆盖报告和行动候选

- 对应需求：RES-05, RES-06, RES-07。
- 工作：输出问题覆盖表、来源和阶段结论；将用户选择的行动交给 ACT，将要事候选交给 EVT，避免重复新建同一任务。
- 代码入口：server/work-tasks.mjs；src/WorkTasks.tsx；src/Artifacts.tsx。
- 完成证据：RES-A05；外部密钥缺失时验收标为依赖未满足，而非伪造通过。
- 顺序：先满足本步骤引用的数据/接口依赖；已满足的部分记录证据并跳过，不能为打勾重复开发。

### RES-P05 · P0 · 计划门槛及时间/费用账本

- 对应 RES-09 / RES-A08；两个学习模板都经计划确认。引入累计执行时间、费用预留/结算及价格版本；计划、重试、搜索、知识降级统一核算。
- 调用前预估保守上界、设置超时和最大输出；预算临界时停止发起新调用，保留并交付已有内容。服务重启/恢复不重置账本；无可靠价格时显示限制，不承诺未知付费接口可控。
- 仅用可控时钟和费用桩验证边界，不真实跑满5分钟或为测试耗1元；另以选定接口小样本核实返回用量与计费口径。

## 4. 数据兼容与失败处理

- 需要迁移时先保存一致性备份和 schema/version 信息；旧实体/引用/文件 ID 保持可解释，迁移可重入。只加兼容默认值，不伪造历史确认或完成状态。
- 先在隔离 DATA_DIR、临时来源目录和模型桩验证错误路径，不清空在线数据或用真实 E 盘做删除测试。
- 对外部服务不可用、缺密钥和人工确认等待，写明受影响的步骤及恢复条件；继续能独立完成的步骤。不能用假结果代替外部验收，也不能无限重试消耗模型。
- UI 保留输入并显示操作状态、失败原因和恢复入口；已有主题、Markdown 阅读和长内容滚动不因改动退化。

## 5. 最小验证集

复用 `tests/web-search.test.mjs`、`tests/phase2.test.mjs`；模拟联网失败后自动调用生成 API、部分证据保留、未核验标签、生成 API 同时失败及手工接力，最后做一个有公开来源的真实调研。没有联网凭据时完成本地、模型知识降级与手工路径，不声称自动联网已实测。

涉及 TypeScript 时运行 `npm run check`；准备交付网页变更时运行一次 `npm run build`。浏览器仅选相关桌面测试，例如 `bash scripts/test-browser.sh <对应测试文件> --project=desktop`。不运行 mobile、android、native-bridge 或无关全套回归；已有通过结果可复用，只有新增改动/失败才重测相关部分。

将实际命令、结果、失败修复、剩余未验证项记入模块交付记录。spec 验收表中的案例要逐项有结果或明确依赖说明，不能仅写“测试通过”。

## 过滤与校验实施门槛（2026-09-29）

对应本模块 spec 的校验补充与 [风险审查](../14-filter-validation-review.md)。并入现有数据契约/接口/交互步骤，不另起重写工程；先校验后副作用，前端使用同一有效性规则并展示失效项。

- **V01 完成证据：** 模型返回 null、错类型、超长正文、非法枚举和越权字段：无副作用，错误可定位；合法响应可直接进入相同保存校验。
- **V02 完成证据：** 选中后翻页、删对象、切换类型：仍可看见与移除旧选项；合法选择提交成功，无隐藏阻塞项。
- **V06 完成证据：** 超时可降级；取消后无新请求；引用失效提示具体来源；生成失败不产出伪成功报告。
- **V07 完成证据：** 返回虚构来源 ID、仅搜索摘要、部分失败后知识回答：标签和覆盖度准确，未知出处不能显示为已查证。

只补当前改动相关反例与一条保存后重开的网页主流程；未经代码与测试验证不得将本文风险标为已关闭。用户尚未回答的产品选择保持待讨论，不在迁移或校验默认值中代为决定。
