# 超强检索 spec

版本：2026-09-28 · 模块编号：RET · 范围：网页端与服务端。

本文区分现状与目标；“必须”描述待验收规范，不代表代码已全部做到。与 [实施计划](<超强检索plan.md>) 配套，跨模块规则见 [总索引](README.md)。来源为 [V1 基线](../09-v1-overview.md)、[第二阶段方案](../10-phase2-product-plan.md)、[首轮实施记录](../11-phase2-implementation.md) 与本次代码核对。新设计细节是本次整理的实现目标；未来扩展不能被自动执行器当作已获授权。

## 1. 目标与模块责任

不记得文件名也能从个人资料中找回可信的相关段落，清楚知道资料是否已复制、解析和索引，并能接着讨论或执行任务。

## 2. 当前实现与缺口

### 已有基础

`server/library.mjs` 已有扫描、规则初筛、SHA-256 去重复制、全文提取、约 1,800 字分段及字符位置、暂停继续和待判断清单；副本在 `.data/library/`。`server/retrieval.mjs` 已有 Qdrant dense + 哈希词项 sparse + RRF、后台索引、版本/状态检查。记录、要事、资料和 active 记忆进入索引。`src/LibraryFiles.tsx` 有搜索、正文、下载及引用到搭子入口。
11 文档报告本机曾接入 20 项、解析 14 份、重复 1 份、待判断 5 项，跑通过真实 Qdrant/BGE-M3。这是历史验证样本，不是现在全盘覆盖率或精度承诺。

### 需要补齐

现有筛选主要看目录与扩展名，不等于理解资料价值；清单只截取最近 500 项，没有完整分页；项目/目录/类型/日期组合筛选、逐文件索引完成状态和命中位置导航尚不完整。副本去重、归档后 canonical 指向及索引失败重试需补边界验证；没有 20 个标注问题的真实精度证据。

## 3. 范围与非目标

本轮完善文字资料检索与可靠接入，兼容现有手动电脑文件导入。E 盘仅作只读来源；只在 PersonalAgent 中管理副本。扫描 PDF OCR、音频转写和复杂表格理解不作为文字检索完成的前置条件；未解析内容必须明示。

## 4. 用户流程

选择来源目录 → 只读盘点与规则初筛 → 显示数量、体积、理由及待判断项 → 分批复制并校验 → 解析 → 后台分段索引 → 自然语言/词项搜索 → 查看命中段落与原副本 → 引用讨论或关联任务。
再次扫描只补充变化；源文件删除不删除副本。暂停停止派发新文件，允许当前原子步骤收尾，恢复从持久进度继续。

## 5. 数据与状态契约

沿用 `libraryFile`、`search_outbox`、`libraryJob` 和 SQLite 权威数据。扩展目标字段：canonicalId/duplicateOf、sourcePaths、hash、sourceMtime、copyName、project、tags、parseState、indexState、indexedRevision、indexError、chunkCount。不要让解析 ready 同时代表向量索引已完成。
分段保留 entityId、revision、chunkId、start/end，能提取时加 page/section；无页码时只显示字符范围。Qdrant payload 保存类型、项目、有效状态及版本，SQLite 回查为最终裁决。索引模型/分段策略变更使用版本标识迁移，不覆盖唯一可用索引。

本节新增字段是目标契约，不是已落地 schema。实现时优先兼容既有实体，迁移前备份，禁止为了符合新字段丢弃历史数据。

## 6. 功能与异常要求

| 编号 | 要求 | 具体行为 |
| --- | --- | --- |
| RET-01 | 来源边界 | 所有来源路径都经过根目录与 realpath 校验；不重命名、删除、移动或写入 E 盘原件。未知文件保留路径和理由，不能静默丢弃。 |
| RET-02 | 接入与版本 | 保存复制清单、内容校验、其他同内容来源及历史版本；失败不丢原件。重扫、重试、重启不制造相同副本。体积限制与磁盘不足须说明原因。 |
| RET-03 | 完整正文 | TXT/MD/文字 PDF/DOCX 的完整提取文本进入分段流程，不能只索引开头。解析异常、乱码、无文字层和截断有单独提示。 |
| RET-04 | 混合检索 | 默认用 embedding dense 和词项 sparse 融合；支持项目、目录、类型、日期、状态的组合过滤。过滤在召回/有效性校验阶段落实，不仅过滤页面上的少量候选。 |
| RET-05 | 可信结果 | 结果包括资料名、片段、位置、来源类型、版本、可打开的副本及匹配说明。分数不是真实性概率；不相关问题允许无结果。旧版本、未确认/暂停/失效记忆不参与默认检索。 |
| RET-06 | 异步与故障 | 提问不等待全库索引。逐文件和总体进度可见，失败可重试。向量服务不可用时明确报错或明确标为关键词降级，不能冒充语义检索。 |
| RET-07 | 可用入口 | 清单分页并支持待判断批量处理、查看筛选理由；搜索段落可定位、引用、关联任务。目录/批次处理不要求逐文件反复审批已授权规则。 |

## 7. 验收标准

| 编号 | 场景 | 可检查结果 |
| --- | --- | --- |
| RET-A01 | 源文件不变 | 导入后比对源文件哈希；删除测试源文件后副本仍能打开，重扫不产生重复正文。 |
| RET-A02 | 找回长文尾部 | 测试资料关键事实在 8,000 字之后；查询返回正确文件和包含该事实的段落位置。 |
| RET-A03 | 状态与版本 | 更新、归档、去重、暂停记忆和删除后，旧向量即使残留也不能作为当前结果返回。 |
| RET-A04 | 可恢复接入 | 复制/embedding 失败及一次服务重启后从进度继续；不能把失败文件显示成已索引。 |
| RET-A05 | 检索质量 | 选 50–200 份有代表性的已授权资料；先确定 20 个自然语言问题及期望文件，再检索，至少 16 个问题的前 5 个去重文件命中。另加少量无答案题检查伪命中；记录失败，不改答案凑数。 |
| RET-A06 | 组合过滤 | 跨项目同名资料、时间区间和类型过滤结果正确；超过 500 项仍能分页找回旧资料。 |

“已有测试通过”仅代表其覆盖的路径；模型请求能返回、页面能打开或接口 health 正常，不足以证明整个模块达标。

## 8. 依赖与后续边界

依赖 SET 的配置/日志和 REC 的原文/附件契约；为 CHAT、MEM、RES、ACT 提供统一来源。先做状态与返回契约，其他模块可用固定样本接入，不必等全盘索引。

范围说明：记录端 ASR 按 Q01/REC-P07 纳入本轮，已完成转写文本可进入检索；不能用本模块的扩展列表排除录音总结。全资料库历史音频批量转写、扫描文档 OCR、复杂表格解析、自动主题聚类及全盘扩展仍另行排期。需先明确服务、成本和范围；不得用“已复制”掩盖不可解析。

## Embedding 选型补充：使用 Qwen

用户已于 2026-09-29 确认选用 **`Qwen/Qwen3-Embedding-0.6B`**，采用本地部署、完整 1024 维向量，供长期记忆与资料检索共用。该选型已确认，不再是待选建议；模型在本机的速度和检索准确率仍需迁移时实测。4B/8B 不属于本次默认选型，不自动升级。

Qwen Embedding 负责 dense 语义向量，关键词 sparse 与 Qdrant RRF 融合继续保留。长期记忆正文、确认状态与来源仍由 SQLite 管理。记忆和资料查询使用匹配的模型与预处理，不能用普通 Qwen 聊天模型代替专用 Embedding 模型。

此前 BGE-M3 是已有实现基线，不因文档更新自动替换。切换需新建模型/维度/预处理版本明确的 Qdrant 索引，全量重算相关向量并验证后再切流；维度相同也不能混用不同模型的向量。

依据：[Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)、[官方 GGUF 版本](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B-GGUF)。

## 过滤与校验补充（2026-09-29）

遵守 [校验审查中的共同契约](../14-filter-validation-review.md)：候选、已选与可提交使用一致规则；无效已选项必须可见可移除；模型建议不等于有效业务数据。以下是目标约束，不代表代码已修复。

- **V01：** 模型返回值先校验对象结构、类型、长度、枚举及引用。标题/摘要/分类等业务内容超限不能无提示截断；无效必填字段显示具体原因。模型不能写 priority、confirmed、active、revision 等人工/服务端字段。关联建议可过滤去重，但必须返回被移除项的原因；用户已确认输入不能静默过滤。
- **V02：** 候选列表、已选列表和提交校验共用类型/空间/状态/自身排除规则；候选缺页不代表对象失效。已有选项即使不在当前页，也须显示摘要或失效占位及移除入口。提交时重新核验，失败保留草稿，按字段及具体 ID 返回原因。
- **V03：** 过滤在 dense 和 sparse 两路落实；融合后回查 SQLite 当前范围/状态/版本，按稳定游标补取到数量或耗尽，设预算并说明截断。所有实体种类采用相同项目语义，通用记忆按适用范围单独判定，不以 kind=memory 一概放行。
- **V04：** 内容去重与来源成员关系分开：保留每个来源路径、项目和版本；按来源关系过滤，再解析 canonical 正文。删除一个来源不自动删除其他来源可用副本；路径/副本选择仍受 E 盘只读边界约束。
- **V05：** 索引命名空间绑定实际模型版本/维度/预处理/分段版本；异步写入前后核验源版本，陈旧任务不能清掉新任务。记忆冲突检查合并尚未索引的有效数据库变更；无法保障覆盖时保留候选并阻止激活，不把部分检索说成检查完成。

## Q04 已确认：统一项目入口

用户已在对话中确认：点击 PersonalAgent，可以一起找到相关笔记、要事、项目文件及其他项目内容；不同来源的搭子会话各自保留，不合并。

共享 project 使用稳定 ID；项目类别显式关联 projectId，各模块按同一 ID 查询，不能用名称相同猜测关系。入口按内容类型分组且可分页，分别显示空/加载/失败，部分模块失败不能把整个项目说成无内容。旧项目字符串保留，映射不明确的先显示待关联，不静默合并同名项目；改名不改变 ID、引用或 threadId。聚合页面不等于把项目全量资料送入每次聊天，模型仍按问题、范围和预算读取。
