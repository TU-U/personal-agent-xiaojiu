# 快速学习与调研 spec

版本：2026-09-29 · 模块编号：RES · 范围：网页端与服务端。

本文区分现状与目标；“必须”描述待验收规范，不代表代码已全部做到。与 [实施计划](<快速学习与调研plan.md>) 配套，跨模块规则见 [总索引](README.md)。来源为 [V1 基线](../09-v1-overview.md)、[第二阶段方案](../10-phase2-product-plan.md)、[首轮实施记录](../11-phase2-implementation.md) 与本次代码核对。新设计细节是本次整理的实现目标；未来扩展不能被自动执行器当作已获授权。

## 1. 目标与模块责任

围绕一个具体问题，用个人资料和必要的外部证据形成可核查的学习路径、比较结论或可行性判断，减少用户重复整理背景的负担。

## 2. 当前实现与缺口

### 已有基础

当前复用 `workTask`：能从话题创建计划，执行本地检索、read_library、search_web、read_web，生成 Markdown 成果；联网未配置可等待外部资料。搭子另有搜索简报。真实本地调研产物已出现，但不是完整外网调研与学习效果验收。

### 需要补齐

没有独立的研究类型与结构化问题覆盖表；工具日志与报告事实未做逐项来源映射，列出若干来源不保证引用支持结论。外部资料回填当前主要是日志字符串；搜索摘要和网页全文的证据等级需统一。新增确认目标：联网失败后自动使用 API 模型已有知识继续研究，而不是默认卡在等待外部资料；此降级流程尚待实现。

## 3. 范围与非目标

面向生活问题、轻量项目 idea、学习和比较，不默认变为复杂项目咨询。共享帮忙做事模块的执行器，不能另造一套任务引擎。生成教程不表示用户已经学会。

## 4. 用户流程

用户提问/引用资料 → 整理目标、背景、关键问题、已知条件和资料缺口 → 展示计划 → 用户确认 → 本地证据与必要外部查证（联网失败则自动以 API 模型已有知识继续）→ 固定结构报告 → 用户讨论/修改 → 可生成行动任务或要事候选。

### 联网失败后的默认路径（2026-09-29 用户确认）

- 联网搜索或网页读取失败、超时、限流、缺少搜索配置时，保留已取得的本地资料和有效网页证据，自动调用已配置的生成模型 API，使用模型已有知识继续解释、比较并提出建议；不要求用户先去网页搜索才能得到结果。失败仅影响部分来源时，只对缺失部分降级。
- 界面和报告明确显示“联网失败，已使用模型已有知识继续；相关内容未联网核验”，附简短失败原因。模型知识属于已有知识回答，不是真实执行搜索；不得生成虚构引用、网页内容、获取时间或搜索成功状态。
- 对最新价格、政策、版本等时效性事实，保留待核实标记；可以给一般原理、假设和验证方法，但不能把未核实事实写成确定的新近结论。关键事实不足时仍交付可用部分并列出缺口。
- 保留“重试联网”和“去 DeepSeek 网页搜索”的可选入口。仅用户选择网页接力后才进入等待回填；降级本身不强制进入等待。回填或重试成功后，在同一任务中补充证据并更新报告，保留版本。
- 生成模型 API 也失败时，显示真实错误，保留输入、已获取资料和已有结果并允许重试；不生成伪成功成果。恢复沿用共享执行器的取消和幂等约束，预算使用本模块已确认的每次5分钟/1元上限，不使用 ACT 草案的10分钟。

### Q08 已确认：先确认计划，单次限 5 分钟 / 1 元

简单解释和分步学习方案都支持，但本模块每次都先展示计划并经用户确认，再执行研究；不自行增加“简单问题免确认”的分支。该规则不强加给搭子的普通聊天。

每次调研上限为 5 分钟、人民币 1 元，先到任一上限就停止新调用并交付已有阶段结果。作为实现口径，从本次生成计划开始累计系统实际处理时间和费用；用户审阅计划或外部网页等待不占执行时长，恢复后继承剩余额度。此口径是工程解释，界面明确显示，不伪称用户逐字指定了计费细节。

计划、搜索、生成、重试和失败后知识回答共用预算账本，不能重试就清零或多线程各享一份。每次调用前预留最大可计费用/输出，完成后用真实用量结算；没有可信价格或可约束计费时，不盲发可能超限的付费请求，并指出缺少配置。预留收束额度，余额不足时输出已保存的阶段结果，不再额外发一次超额“总结”。取消和总时限使用服务端控制；中断请求不代表供应商一定退款，费用保证需按实际接口计费能力验收。

## 5. 数据与状态契约

在共享 workTask 上扩展 researchBrief（topic、background、questions、constraints、type、asOf、expectedOutput）。研究 evidence 保存 sourceId/url、revision、snippet、locator、retrievedAt、evidenceType（原文/搜索摘要/用户回填）及待核实状态。
额外记录 researchMode（web_verified / mixed / model_knowledge）、fallbackReason 与失败步骤；只有相应结论有实际网页证据支持才标为已联网核验，搜索请求成功本身不够。模型已有知识结论单独标记 basis=model_knowledge、verificationStatus=unverified，不伪造 evidence 的 sourceId/url/retrievedAt；问题覆盖状态与是否核验分开记录。上述模式是来源说明，不替代 artifact 的生成方式 mode=model。
artifact 复用成果存储，追加研究类型及 questionCoverage。问题覆盖和来源版本属于本次研究，不自动写入长期记忆。

本节新增字段是目标契约，不是已落地 schema。实现时优先兼容既有实体，迁移前备份，禁止为了符合新字段丢弃历史数据。

## 6. 功能与异常要求

| 编号 | 要求 | 具体行为 |
| --- | --- | --- |
| RES-01 | 研究入口 | 支持快速学习、方案比较、可行性分析三种轻量模板，可自定义；引用现有记录/要事/副本及话题上下文，不重复手填已知背景。 |
| RES-02 | 先明确问题 | 计划展示关键问题、已知/未知、预期产物与检索范围；缺非关键资料时注明假设继续，关键事实不足则保留进度等待补充。 |
| RES-03 | 双搜索路径 | 应用内搜索当前是 Brave + 配置的生成模型；不把 DeepSeek 网页联网功能说成已有 API 功能。另一条路径输出可编辑简报，列背景、关键信息、问题、关键子问题和固定回答格式，跳转 DeepSeek 后等待用户带回结果。 |
| RES-08 | 联网失败自动降级 | 联网失败或不可用时，自动调用配置的生成模型 API，以已有知识和已获取资料继续；显式标注未联网核验和失败原因，保留可选重试/网页接力；模型 API 也失败则报错并保留进度。 |
| RES-04 | 证据分层 | 区分本地原文、网页全文、搜索摘要和手工回填；保留链接/文件版本、引用片段及获取时间。需要新近事实时联网或明确未核实，不能仅凭模型常识伪造查证。 |
| RES-05 | 固定交付 | 学习报告：结论、概念与前置知识、最短学习路径、小练习、来源与待核实项。调研报告：问题、结论、事实依据、选项比较、适用条件、风险/未知、最小验证动作、来源与日期。 |
| RES-06 | 覆盖与收束 | 报告标明每个关键问题已回答/部分回答/缺证据；预算末尾交阶段结果，不无限搜索。证据不足可以得出“暂不能判断”。 |
| RES-07 | 行动衔接 | 只生成建议的行动/要事候选，用户选择后关联共享任务或保存要事。AI 不替用户指定要事等级，不把学习资料当完成证明。 |
| RES-09 | 计划与预算 | 每次先确认计划；简单解释/学习方案均支持；系统执行累计不超过5分钟，调用费用预算1元，重试/降级共用账本，触限返回阶段结果及原因。 |

## 7. 验收标准

| 编号 | 场景 | 可检查结果 |
| --- | --- | --- |
| RES-A01 | 学习场景 | 引用一份长文，得到含来源位置、概念解释、顺序与练习的学习路径；没有虚构用户已掌握。 |
| RES-A02 | 比较场景 | 至少两个方案按同一维度比较，关键事实可回到实际获取的原文，未知单列。 |
| RES-A03 | 双路径 | 搜索不可用时默认先交付模型已有知识回答；用户仍可选择编辑简报并进入网页接力等待；回填来源后在同任务继续，没回填时不显示已联网完成。 |
| RES-A04 | 时效与冲突 | 个人记录与新网页冲突时同时展示时间和差异，不静默用新网页改用户原文。 |
| RES-A05 | 交付完整度 | 每个关键问题有覆盖状态；缺证据或额度到达仍有可查看的阶段报告和下一步。 |
| RES-A06 | 自动降级 | 模拟超时、限流或缺少搜索配置，生成 API 正常：无需额外确认即可继续给出已有知识回答；保留已有证据，界面与报告注明降级原因和未核实项，无虚构来源。 |
| RES-A07 | 双重失败与恢复 | 联网与生成 API 均失败时明确报错、保留进度；重试或网页回填成功后更新同一任务和报告版本，不重复创建任务或伪造已核验。 |
| RES-A08 | 预算边界 | 未确认不执行研究；可控时钟和用量验证5分钟/1元先到即收束；并发、失败重试、降级不重置预算；未知价格不能假称已满足费用上限。 |

“已有测试通过”仅代表其覆盖的路径；模型请求能返回、页面能打开或接口 health 正常，不足以证明整个模块达标。

## 8. 依赖与后续边界

依赖 RET、REC 与已有共享执行器；只补本模块必要的持久化/恢复/预算能力，不等待或启动整套待讨论的 ACT-P0。向 EVT/SUP 输出候选或任务引用，不直接确认。

P2：多站点持续监测、复杂爬虫、付费数据库、学术文献管理和长课程系统。

## 过滤与校验补充（2026-09-29）

遵守 [校验审查中的共同契约](../14-filter-validation-review.md)：候选、已选与可提交使用一致规则；无效已选项必须可见可移除；模型建议不等于有效业务数据。以下是目标约束，不代表代码已修复。

- **V01：** 模型返回值先校验对象结构、类型、长度、枚举及引用。标题/摘要/分类等业务内容超限不能无提示截断；无效必填字段显示具体原因。模型不能写 priority、confirmed、active、revision 等人工/服务端字段。关联建议可过滤去重，但必须返回被移除项的原因；用户已确认输入不能静默过滤。
- **V02：** 候选列表、已选列表和提交校验共用类型/空间/状态/自身排除规则；候选缺页不代表对象失效。已有选项即使不在当前页，也须显示摘要或失效占位及移除入口。提交时重新核验，失败保留草稿，按字段及具体 ID 返回原因。
- **V06：** 错误必须分类：搜索不可用、超时、限流等能力错误可降级；取消、访问拒绝、输入非法、源版本冲突不能被当联网失败。只降级缺失证据部分，保留已有证据；生成 API 再失败则报错。缺证据交阶段结果与主动网页接力等待分开。
- **V07：** 报告引用仅允许本次真实获得且可定位的证据 ID；全文/摘要/回填/模型知识逐条区分。程序校验引用存在及版本，不能声称由结构校验保证事实正确。混合报告逐结论注明未核验，问题覆盖状态不能由模型任意 ID 增删。

## 已确认技术栈接入（2026-09-29）

本轮使用 LangGraph JS 管理调研图状态和持久检查点，Redis + BullMQ 管理后台执行，SQLite 管理业务状态、确认和预算（TECH-01/02）。等待用户确认不持续占住执行资源；恢复不能越过确认、重置预算或重复生成成果。图执行不扩展 ACT 未定工具权限；联网失败仍按已确认规则降级。必须有实际图执行及重启恢复证据，不能把仅安装依赖视为完成。
