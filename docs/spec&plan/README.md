## 3. 全局不可破坏的规则

1. **仅网页端与服务端。** 不修改、撤回、打包或测试 `mobile/`；不运行 android/native-bridge 测试。网页开发可实时预览，不能要求每次先打 APK。
2. **E 盘只读。** 接入时筛选有意义内容并复制到 PersonalAgent；未知内容保留清单，明确垃圾跳过。后续整理、解析和执行只管理副本。不得以任务工具或迁移为由删除、移动、改名或覆盖原件。
3. **保留数据。** SQLite 为权威状态，Qdrant 是可重建索引；迁移先备份，旧实体和文件引用兼容。测试用隔离目录；线上恢复、删除原数据不是一般开发验证步骤。
4. **人工确认边界不变。** 记忆只有用户选中且解决冲突后生效；要事等级由用户选择，所有要事到点后等用户确认；任务工具完成和产物生成不代表用户现实任务完成。
5. **AI 失败必须可见。** 规则摘要/原文摘录不能标作 AI 输出；检索服务降级不能标作语义结果；外部网页接力不能标作后台搜索完成。后端打印可追踪日志，但不打印密钥和内联图像。
6. **保持个人使用边界。** 用户允许演示口令，不重建强制改口令门槛；不新增公网部署、对外发布、消息发送或支付能力。
7. **不过度测试。** 覆盖本次关键路径和失败边界，复用已有通过结果；不为了结束任务反复跑全量套件。没有真实证据的验收如实标未验证，不凑通过率。
8. **记账文件不由本次改写。** 其用户原文里的需求不因其他模块的 P2 表述失效。例如记账 OCR 的范围以用户文档为准；不自动扩大成整个资料库 OCR/ASR 已完成。

## 4. 模块之间的共同契约

### 数据所有权

| 对象 | 负责模块 | 其他模块怎么使用 |
| --- | --- | --- |
| project / noteCategory / classificationCorrection | REC / SET | 项目统一入口、记录单分类与纠错问题表；各模块按稳定 projectId 关联 |
| note / attachments | REC | 通过 id、revision、来源片段引用；不覆盖原文 |
| libraryFile / 分段索引 | RET | 读取副本与匹配段落，区分解析和索引完成状态 |
| conversation / threadSummary | CHAT | 同话题上下文；摘要非长期记忆 |
| memory | MEM | 仅 active 且 scope/版本/来源有效时读取 |
| event / 图片快照 / 复核 | EVT | 只读引用或用户选择后保存，不自动确认 |
| workTask / workStep / toolInvocation | ACT | RES 填研究目标；SUP 关联执行实例；runner 只有一套 |
| workRun / evidence / timer / reminder | SUP | 负责某日实际投入与验收，不能用 workTask.review 代替 completed |
| artifact / 正文版本 | REC | ACT 提交产物，RES 提供内容结构，SUP 关联证据 |
| provider/settings/logs/backup | SET | 各模块使用同一能力配置与追踪约定 |
| pet 提示表 / 反馈状态 / 短会话 | PET | 展示各模块统一监督提醒；源模块管事实与确认；情绪聊天不默认接收业务资料 |
| 账单数据 | 用户记账文档 | 独立规则；本次不替用户推导 schema 或计算逻辑 |

历史实体 `task` 是成果生成作业，`workTask` 才是第二阶段任务。代码改造前明确两者，不能用同名重构把历史状态合并丢失。

### 引用与证据（目标公共契约）

跨模块引用至少包含 `kind + id + revision + title + quote/locator`；外部网页另有 `url + retrievedAt + evidenceType`。locator 优先页码/章节，不能提取时用字符区间。区分“活对象引用”和“当时引用快照”：来源变化不能悄悄改历史证据，也不能把旧快照冒充当前事实。

向量相似度、模型判断、用户事实、网页摘要、实际工具结果是不同证据。成果中的关键判断需能回到支持它的片段；一串来源列表本身不证明事实成立。删除/失效对象在读取时检查权威库，不能只等索引后台清理。

### 全局监督提醒统一交给小九（最新用户要求）

所有提醒、监督相关提示必须绑定小九，由小九台词表达，汇总到 hover 可见的独立提示表；「提示语」切换常驻，空表显示“无”，有未处理项时左上角有提示标识。详见 [小九 spec](小九桌宠spec.md) 与 [示意图](assets/小九功能更新.png)。此要求覆盖旧文档中“小九不读取业务提醒”“主动任务提示待确认”的限制。

SUP、EVT、REC、MEM 等继续决定真实状态、调度与确认；PET 聚合并展示，不重复建调度器。原模块保留详情、状态和处理操作，不再独立弹一套催促；原处展示督促文案也复用小九身份与同一消息。普通表单错误、保存 toast 仍就近显示。后续记账的约定查看账单提醒同样接入，记账原文不改。

提醒展示层可读取必要业务事实，不等于将全量资料注入小九的情绪聊天模型。摸摸、关闭表、看过消息或跳到成果页均不确认任何事项。PET 的公共提醒契约在阶段 1–2 与源模块同步定义，完整 UI 在阶段 4 验收，不等所有模块完工才补接。

### 日期、任务状态与副作用

当前产品日期以 Asia/Shanghai 为基线，保存时间点用可解析时间戳，按日对象有明确 localDay。跨模块不得一个按 UTC、一个按浏览器日期，从而产生重复日任务。

研究/执行任务到 `review` 表示产物待检查；每日实例到 `completed` 需要条件达成与用户确认；要事的本次检查确认与整个要事结束分开；旧 event.confirmed 不能同时代表两者。任何一个都不能自动传染成另一个状态。

复制、提交产物、生成日实例、发送应用内提醒和确认记忆必须可去重，并留下操作/版本证据。服务重启时恢复“可继续状态”，不是默默重放所有有副作用的动作。计划与工具权限变更不能靠资料中的提示词获得授权。

## 5. 开发顺序与依赖

以 [总执行文档第 5 节](../19-goal-execution.md#5-默认执行顺序) 为执行顺序：SET 公共基础 → REC → RET → MEM → CHAT → EVT → SUP → RES → 记账 → PET → SET 收尾及全局联验。公共提醒、稳定会话和项目契约提前建立，跨模块验收在依赖就绪后闭环。一个外部依赖受阻时继续独立工作，受阻项不能从必需验收中删除。

ACT 独立场景不进入默认开发；RES/SUP 所需的持久步骤、幂等和预算等共享能力按已确认需求实施。18 号技术栈已确认：Redis + BullMQ、LangGraph JS 调研试点、Zod 纳入本轮，按 TECH-01–03 实际接入并验收；其他 MQ 不引入。

## 6. goal 使用与完成条件

使用本页顶部指令即可引用完整执行约定。goal 是持续目标，不是预约启动；实际开始时再提交。每步留下需求覆盖、修改、验收证据、使用入口和下一步，模块验收通过后直接继续，不逐个等用户批准。详细规则见 [总执行文档](../19-goal-execution.md)。

本轮全模块范围包含用户记账文档及最新补充；其他已确认 P0/P1 与追加条款一并执行，P2/待讨论项不自动增加。只有范围内全部必需验收通过才完成目标；缺外部服务或真实验收时如实记为受阻，不用阶段总结冒充全部完成。

开发代理的 goal 不等于应用里的 workTask；应用用户确认业务计划的规则也不意味着每个已经授权的代码修复都要重新向用户请示。
