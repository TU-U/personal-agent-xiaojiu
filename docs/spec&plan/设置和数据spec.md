# 设置和数据 spec

版本：2026-09-28 · 模块编号：SET · 范围：网页端与服务端。

本文区分现状与目标；“必须”描述待验收规范，不代表代码已全部做到。与 [实施计划](<设置和数据plan.md>) 配套，跨模块规则见 [总索引](README.md)。来源为 [V1 基线](../09-v1-overview.md)、[第二阶段方案](../10-phase2-product-plan.md)、[首轮实施记录](../11-phase2-implementation.md) 与本次代码核对。新设计细节是本次整理的实现目标；未来扩展不能被自动执行器当作已获授权。

## 1. 目标与模块责任

让用户能自行配置与排查 AI、搜索和数据服务，看到真实调用结果与错误，并有可恢复的数据管理路径。

## 2. 当前实现与缺口

### 已有基础

Settings 已支持模型 URL/名称/密钥、连接测试、Brave key、空间名称、访问口令、网页主题和 AI 日志。服务端 SQLite/附件/资料/产物分开保存；JSON 导出带业务结构数据，但不是含完整二进制的可恢复备份。检索配置主要为环境变量与本机自动发现；Qdrant/embedding 的脚本和日志已有。

### 需要补齐

通用生成连接成功不证明视觉/embedding/搜索也可用；缺统一能力健康状态。检索/任务额度等参数在代码/环境中分散。JSON 导出不含完整副本正文/文件和所有运行配置，不能宣称一键恢复；缺受控恢复流程、迁移版本和校验清单。

## 3. 范围与非目标

当前个人网页空间，保持用户允许的演示口令，不再以“必须换口令”为电脑文件使用前置。不自动暴露公网、不动 E 盘原件、不在文档或前端返回密钥。历史要求所有 AI 交互在后端有日志继续满足，但二进制和凭据不打印。

## 4. 用户流程

打开设置 → 选择生成/视觉、embedding、向量库、搜索能力 → 修改允许配置 → 保存 → 测试该能力 → 查看状态/错误与对应日志。
数据管理：查看存储位置与导出范围 → 导出结构数据或完整备份 → 校验清单 → 如需恢复先到隔离目录试恢复并验证，再明确切换；不能默默覆盖在线库。

### 已确认答复的公共能力

- Q01：ASR 与说话人分离能力分别显示配置、可用性与处理错误；本地优先、免费优先，具体实现以硬件/质量验证选型，不自动付费或假设聊天模型支持音频。
- Q03：问题记录表提供分类纠错的查看、筛选、关联原记录与处理状态，实际存储在项目数据目录。反馈立即持久化，后续开发读取，不是自动给外部人员发消息。纳入完整备份和恢复校验。
- Q08：显示调研时间/费用预算、价格版本、预留及实际用量；已确认5分钟/1元不被通用执行器默认值覆盖。未知计费条件不可标已验证预算可控。
- Q12：账单原文件及截图保留，连同导入批次、用户去重确认和交易关联一起备份；恢复后能从交易回看原件。

## 5. 数据与状态契约

复用 settings、sessions、operations、changes 与 DATA_DIR，不另建配置数据库。模型配置按能力返回脱敏视图，密钥仅 hasKey；真实值由服务端私有配置/设置保存。日志含 callId、task/thread/source 关联、输入摘要/文本、耗时、模式、输出/错误和用量，排除凭据与内联图像。
完整备份目标：schemaVersion、SQLite 一致性快照、uploads/library/task-artifacts 清单与哈希、必要非敏感运行设置。Qdrant 可重建；密钥是否导出必须显式选择，默认不包含。

本节新增字段是目标契约，不是已落地 schema。实现时优先兼容既有实体，迁移前备份，禁止为了符合新字段丢弃历史数据。

## 6. 功能与异常要求

| 编号 | 要求 | 具体行为 |
| --- | --- | --- |
| SET-01 | 能力分开配置 | 生成模型、视觉能力、embedding、Qdrant、网页搜索分别标配置和健康情况。展示保存生效值，不强制把生成模型当 embedding 模型。环境管理的字段说明来源与可编辑性。 |
| SET-02 | 测试真实能力 | 测试请求走同一实际调用路径，空响应/不支持输入/超时/鉴权失败分别显示；health 只代表服务存活，不代表 AI 或保存成功。 |
| SET-03 | 统一错误日志 | 所有 AI 调用含关联 id、请求、输出与错误，后端终端和网页可看；embedding 不输出海量向量，图片不打印 base64，任何 token/key 不进入日志/前端。 |
| SET-04 | 数据透明 | 明确 SQLite、上传原件、库副本、任务产物和 Qdrant 的分工及磁盘状态。JSON 导出标注不含二进制，不冒充完整备份。 |
| SET-05 | 备份与恢复 | 破坏性迁移前备份；完整备份可校验并试恢复到新目录。恢复线上数据是单独明确动作，校验失败不覆盖当前目录；测试不修改真实用户数据。 |
| SET-06 | 访问与开发体验 | 保留个人演示口令可用；仅本地/既有局域网范围运行，不新增公网入口。网页实时开发与构建后运行分开说明；dev 不直接提供 .data 或私有配置下载。 |
| SET-07 | 配置边界 | 调整任务额度、安静时段或检索参数有校验与合理上限，不让模型通过任务内容更改全局设置。用户主题偏好保持浏览器本地语义。 |

## 7. 验收标准

| 编号 | 场景 | 可检查结果 |
| --- | --- | --- |
| SET-A01 | 配置闭环 | 保存模型 URL/名称后刷新仍一致，实际测试使用该配置；空输出和错误在页面与后端可对应到同一调用。 |
| SET-A02 | 能力分离 | 文本测试成功但视觉/embedding失败时分别展示，不显示所有 AI 正常。 |
| SET-A03 | 日志脱敏 | 请求/响应/错误/导出/前端 payload 不含测试密钥和图片二进制，日志仍可定位某条失败任务。 |
| SET-A04 | 备份可用 | 在隔离目录恢复一份含记录、图片、要事、任务、记忆的样本，附件哈希与引用关系正确；损坏清单中止恢复。 |
| SET-A05 | 边界保持 | 演示口令能用电脑文件；开发服务敏感路径不能直接下载；没有新增公网暴露。 |

“已有测试通过”仅代表其覆盖的路径；模型请求能返回、页面能打开或接口 health 正常，不足以证明整个模块达标。

## 8. 依赖与后续边界

数据/配置/日志公共基础，先验证现有实现并支持各模块；完整备份可分步做，不为新增设置重写数据库。线上恢复属于单独明确操作。

P2：多用户、远程云同步、公开部署、权限角色体系。若将来用户明确需要，再单独改变当前个人本地假设。

## 过滤与校验补充（2026-09-29）

遵守 [校验审查中的共同契约](../14-filter-validation-review.md)：候选、已选与可提交使用一致规则；无效已选项必须可见可移除；模型建议不等于有效业务数据。以下是目标约束，不代表代码已修复。

- **V01：** 模型返回值先校验对象结构、类型、长度、枚举及引用。标题/摘要/分类等业务内容超限不能无提示截断；无效必填字段显示具体原因。模型不能写 priority、confirmed、active、revision 等人工/服务端字段。关联建议可过滤去重，但必须返回被移除项的原因；用户已确认输入不能静默过滤。
- **V02：** 候选列表、已选列表和提交校验共用类型/空间/状态/自身排除规则；候选缺页不代表对象失效。已有选项即使不在当前页，也须显示摘要或失效占位及移除入口。提交时重新核验，失败保留草稿，按字段及具体 ID 返回原因。
- **V20：** 配置按能力校验并原子保存；探测结果绑定配置版本，迟到结果不覆盖新配置状态。备份校验schema、实体类型/ID唯一、引用版本、文件清单与哈希、合法相对路径，先隔离恢复；索引版本不能替代权威数据完整性。

## 已确认技术栈接入（2026-09-29）

本轮已确认引入 Redis + BullMQ、LangGraph JS 调研试点和 Zod（TECH-01–03），其他 MQ 不引入。设置必须展示相关服务/worker 的真实状态和错误，日志可关联任务与步骤；启动、持久化、恢复与备份覆盖新增状态。Redis 故障时已保存任务可恢复，不能显示执行成功；SQLite 是业务事实权威。公共 Zod 校验覆盖本轮 API/模型输出/工具参数，合法引用、权限、状态与版本仍由业务层核验。选型已确认，当前实现状态以执行证据为准。
