# 记录&每日待办&成果 spec

版本：2026-09-29 · 模块编号：REC · 范围：网页端与服务端。

本文区分现状与目标；“必须”描述待验收规范，不代表代码已全部做到。与 [实施计划](<记录&每日待办&成果plan.md>) 配套，跨模块规则见 [总索引](README.md)。来源为 [V1 基线](../09-v1-overview.md)、[第二阶段方案](../10-phase2-product-plan.md)、[首轮实施记录](../11-phase2-implementation.md) 与本次代码核对。新设计细节是本次整理的实现目标；未来扩展不能被自动执行器当作已获授权。

## 1. 目标与模块责任

让随手记录足够轻、原始资料完整可读；当天小事可以勾选与回看；需要输出时形成有来源、可编辑和可导出的成果。

## 2. 当前实现与缺口

### 已有基础

记录已有正文、Markdown 渲染、项目标签、图片剪贴板操作、置顶、草稿、导入/原件下载和 AI 归纳。TodoPanel 按日期保存待办并可把旧未完成项复制到今天。成果支持周报/主题整理、编辑、来源与 Markdown 导出，另接 workTask 产物。
上传原件在 `.data/uploads/`，资料副本在 `.data/library/`，任务输出在 `.data/task-artifacts/`；不是一个可互相覆盖的文件目录。

### 需要补齐

V1 上传音频不能自动转写、扫描 PDF 无 OCR；普通导入有正文长度上限，不能把副本全文检索和记录预览截断混为一谈。成果 AI 失败时存在本地整理稿路径，必须继续明确来源模式。任务成果文件和网页编辑内容的版本同步需要核对；多端冲突、图片剪切失败及重复导入要留原内容。

## 3. 范围与非目标

记录是事实载体、todo 是轻量勾选项、artifact 是派生成果；不把三者改造成任务引擎。声音/图片/文字上传都必须保存原件；不支持的解析明确返回“待解析/需补文字”，不能假造总结。录音 ASR 已按 Q01 纳入本轮目标：上传和网页录音、中英文、时间戳及说话人区分。本地优先、优先免费。图片/扫描 PDF/复杂表格的扩展边界按 Q02 暂缓，不把上传文件等同于已具备理解能力。

## 4. 用户流程

随手输入/粘贴图片/导入 → 原件与正文保存 → Markdown 阅读或原文编辑 → 可选 AI 归纳 → 引用讨论/转为要事/关联任务。
每日待办：选择日期 → 新增/勾选 → 历史回看 → 用户选择带到今天。
成果：选资料范围与用途 → 生成 → 显示模式和来源 → 核对编辑 → 保存版本 → 导出/作为证据。

### 已确认：直接进入固定搭子会话（2026-09-29）

所有记录提供“与搭子讨论”入口，点击自动引用并跳转：首次建立关联，以后一直返回同一会话，跨天、改名和编辑正文都不另开。重新进入时引用最新已保存版本，既有对话和历史引用版本保留。关联按来源类型与稳定 ID 保存，不按标题或版本创建；共用 CHAT 的幂等映射接口，不在本模块另造会话规则。详见 [搭子 spec](搭子spec.md) 的“从来源回到固定讨论”。本条为确认目标，尚待开发。

### 已确认：记录分类（2026-09-29）

所有记录都需要分类。固定类别按用户给出的名称和顺序展示：

1. 日记
2. 理财
3. 读书笔记
4. 个人工作
5. 生活
6. 感悟
7. 灵感
8. study plan
9. Q（问题）

开发项目的记录支持新建独立的项目类别，例如 PersonalAgent；它是记录分类中的单独入口，不只是“个人工作”下的一枚标签。其他开发项目也可由用户创建自己的类别，不硬编码为只能有 PersonalAgent。

- 新建、编辑和导入记录均可选择类别；记录列表可按固定类别或项目类别查看、筛选，也能返回全部记录。
- 分类是独立的归档维度，不替代已有标签或项目关联；“理财”记录也不等同于记账模块的交易分类。
- 用户已确认：每条记录只能有一个类别，保留现有标签；AI 自动归类，用户可随时调整。分类失败不阻止原文保存，显示待分类和原因；不能用随意默认类别冒充 AI 结果。人工调整后立即写入问题记录表，供后续开发排查。
- 历史记录保留正文、附件和 ID；没有可靠分类的显示“待分类”待用户整理，这是迁移状态，不增加第十个固定类别。支持批量选择历史记录后归类，避免逐条重复编辑。
- 调整记录类别或项目类别名称不改变记录 ID，不重建其固定搭子会话，也不破坏要事引用及历史版本。类别使用稳定 ID；空名称和重复创建应校验，失败保留输入与原分类。

以上为已确认分类需求及明确标注的实现默认，尚未表示应用已实现。

### 已确认答复：录音、分类纠错与待办升级

来源：[用户答复 Q01/Q03/Q07](../13-requirements-answers.md)。以下是开发目标，不是已上线说明。

- 录音支持上传已有文件和网页直接录制；主要处理中英文，转写须有时间戳与说话人区分。保留原录音、分段转写及可编辑文本，再基于转写生成总结；说话人用“说话人 1/2”标识，不凭声音猜真实身份。用户没有要求边录边实时显示文字，不默认将其加入本轮。
- ASR 本地优先，优先免费；具体模型、硬件可行性及最长录音时长尚需技术核验/样本，不擅自承诺无限时长或自动切付费云服务。浏览器录音权限失败、服务不可用、说话人分离失败分别可见，部分转写不得冒充完整成功。
- 工程契约：audioAttachmentId、sourceRevision、transcriptRevision、language、segments（startMs/endMs/speakerId/text）、处理状态与错误；原文、转写、总结分别保存。分段时间必须合法、递增且在音频时长内；分块边界去重不丢字。修订转写使旧总结可辨认地过期。
- 分类只有一个 categoryId；AI 从九个固定类别和用户已建项目类别中自动选择，不自行创建类别。用户改类后，记录 classifierRevision、旧/新类别、来源记录及版本、模型/提示版本、时间和简短理由（可选），生成 classificationCorrection 问题记录。保存分类和问题记录要一致成功或明确失败；同一操作重试不重复登记。
- 问题表中的反馈供后续开发修复，不等于模型自动训练或自动修改程序。迟到的自动分类不能覆盖人工调整；分类失败也不能丢原文。记录转要事后各有自己的搭子会话，不继承原记录会话（Q05）。
- 普通待办可显式升级为监督任务，保留来源关联。升级前让用户确认完成要求；升级后的主页/小九不要重复催同一件事，普通勾选不能绕过计时、证据及人工确认。

## 5. 数据与状态契约

目标新增 noteCategory（稳定 id、name、kind=builtin/development_project、sortOrder）及 note.categoryId；固定类别使用稳定键，项目类别由用户创建。历史未归类允许 categoryId 暂空并显示迁移状态，新记录按自动单分类规则处理，失败可暂存待分类，不强制手选后才能保存；不以分类名充当记录或搭子会话标识。
沿用 note、todo、artifact 与旧 task（成果生成作业）。note 保存原文 content、attachments、来源与摘要模式；todo 保存 day、done、completedAt，可扩展 carriedFromId 防止重复搬运；artifact 保存 body、mode、sources、revision，可关联 workTask/run/step。
成果正文与落盘文件必须对应同一 revision；派生摘要或格式转换不覆盖原文。Attachment 的来源与独立快照要能解释删除影响。

本节新增字段是目标契约，不是已落地 schema。实现时优先兼容既有实体，迁移前备份，禁止为了符合新字段丢弃历史数据。

## 6. 功能与异常要求

| 编号 | 要求 | 具体行为 |
| --- | --- | --- |
| REC-01 | 低负担记录 | 文字记录正文必需；纯音频/图片可先保存有效原件；标题/项目/标签可自动建议；未保存内容可恢复。保存需服务端确认，失败时保留输入，不能只凭 health 正常提示已保存。 |
| REC-02 | 格式与图片 | 阅读支持 MD 标题、列表、表格、代码、引用与图片；编辑保留原文换行/编号。图片复制/粘贴/剪切有成功与失败反馈，剪切必须在目标/剪贴板成功后再移除，不能造成原图丢失。 |
| REC-03 | 导入与归纳 | 导入保存可下载原件，展示解析/模型能力、截断和失败原因。AI 归纳失败不显示“AI 草稿”伪装规则结果，重试不会重复创建记录。 |
| REC-04 | 每日待办 | 日历口径一致；按天独立，历史不清空。未完成项带到今天需要用户动作并可识别来源，重复操作不制造多条。待办勾选不替代任务或要事确认。 |
| REC-05 | 成果真实性 | 周报、主题整理和任务产物标明模型草稿/本地原文整理/人工编辑及来源版本；没有有效 AI 结果则报错或明确本地模式。不能将计划写成已完成。 |
| REC-06 | 成果编辑与导出 | 长文和侧栏可滚动，来源可打开；编辑不被后台覆盖，导出的 Markdown 与当前保存版本一致，任务下载链接也遵守同一版本口径。 |
| REC-07 | 关联与删除 | 引用记录讨论、要事图片快照、任务证据能互相定位；删除来源不悄悄删除独立快照。失效引用有标记，相关长期记忆按 MEM 规则失效或待确认。 |
| REC-08 | 来源固定讨论 | 所有记录/要事可一键进入搭子并自动引用；按来源稳定 ID 首次建立关联会话，后续复用，跨天与内容更新不新建；当前引用用最新版本，历史保持原样，失败不能静默新建。 |
| REC-09 | 记录分类 | 固定类别为日记、理财、读书笔记、个人工作、生活、感悟、灵感、study plan、Q（问题）；支持用户为开发项目新建独立类别，记录可归类和按类筛选；迁移保留内容与关联，改分类不改变固定搭子会话。 |
| REC-10 | 录音完整流程 | 上传和网页录音、中英文转写、时间戳和说话人区分；本地优先、优先免费；保留原件和可编辑转写，进度/失败/部分结果可见，再生成总结。 |
| REC-11 | 自动单分类与纠错反馈 | AI 自动选一个合法类别，用户可改；人工改类立即持久登记问题记录，防重复、防迟到 AI 覆盖，不自动改代码。 |
| REC-12 | 待办升级监督 | 显式升级、保存来源、确认完成条件、避免重复提醒；普通勾选不能代替监督验收。 |

## 7. 验收标准

| 编号 | 场景 | 可检查结果 |
| --- | --- | --- |
| REC-A01 | 原文保真 | 粘贴用户提供的多级 Ozon 会议文本，保存、重开、编辑与 MD 阅读均保留章节/编号/换行。 |
| REC-A02 | 图片与故障 | 含多图的复制/粘贴/剪切及一次上传失败不丢原图，刷新后附件关系正确。 |
| REC-A03 | 导入结果诚实 | 文字/图片有成功归纳或明确错误；音频/扫描件不能输出伪总结，原件可下载，截断可见。 |
| REC-A04 | 跨日历史 | 午夜后显示当天列表，昨天完成状态可查；带入一次未完成事项，重复请求不重复。 |
| REC-A05 | 成果一致 | 模拟空模型返回、来源校验失败及人工编辑，模式标签准确，网页和下载版本一致。 |
| REC-A06 | 关联可靠 | 转要事保留图片快照；删除来源后已有要事图片和成果历史可解释，不冒用已失效记忆。 |
| REC-A07 | 固定讨论入口 | 首次点击自动引用；再次点击、双击/重试、跨天、改名/改正文后仍为同一 threadId；最新引用与旧历史同时保留；同名不同来源不串话题；映射加载失败不新增会话。 |
| REC-A08 | 分类与项目类别 | 九类名称准确且顺序一致；创建 PersonalAgent 项目类别并归入记录，刷新后保存、筛选正确；历史未归类可批量整理；移动类别或类别改名后原记录、附件、要事引用和 threadId 均保持；创建失败不丢输入。 |
| REC-A09 | 中英文录音闭环 | 上传与网页录音各走通一次；原件可回听、转写可改，有时间戳及说话人；识别或分离失败有明确状态，正文总结可追溯。 |
| REC-A10 | 分类纠错 | AI 自动单分类；用户改类立即出现问题记录；请求重试不重复，旧 AI 回包不覆盖人工选择，失败不丢原文。 |
| REC-A11 | 待办升级 | 重试升级只创建一个监督关联，主页/小九无双重催促；普通勾选不绕过监督条件；历史仍可追溯。 |

“已有测试通过”仅代表其覆盖的路径；模型请求能返回、页面能打开或接口 health 正常，不足以证明整个模块达标。

## 过滤与校验补充（2026-09-29）

遵守 [校验审查中的共同契约](../14-filter-validation-review.md)：候选、已选与可提交使用一致规则；无效已选项必须可见可移除；模型建议不等于有效业务数据。以下是目标约束，不代表代码已修复。

- **V01：** 模型返回值先校验对象结构、类型、长度、枚举及引用。标题/摘要/分类等业务内容超限不能无提示截断；无效必填字段显示具体原因。模型不能写 priority、confirmed、active、revision 等人工/服务端字段。关联建议可过滤去重，但必须返回被移除项的原因；用户已确认输入不能静默过滤。
- **V02：** 候选列表、已选列表和提交校验共用类型/空间/状态/自身排除规则；候选缺页不代表对象失效。已有选项即使不在当前页，也须显示摘要或失效占位及移除入口。提交时重新核验，失败保留草稿，按字段及具体 ID 返回原因。
- **V11：** 固定类别/项目类别使用稳定 ID；AI 在已存在集合中自动选一个类别，用户可调整并立即登记问题；创建类别仍是明确用户动作。失败保留待分类原文，迟到AI不能覆盖人工修改；旧记录允许兼容状态，移除类别必须处理已有引用。
- **V12：** 决定输入能力时检查实际附件及内容，不只按 note.type。请求记录实际读取的附件 ID/版本/数量，支持范围内的选定图片都纳入；超限或不支持时点名缺失部分并提供拆分，不能默默漏读。OCR/ASR 完成状态与上传状态分开。
- **V13：** 异步草稿绑定来源类型/ID/正文及附件版本和请求序号，返回时检查编辑会话仍匹配；不覆盖后来用户输入。独立图片先完整复制校验，再提交关联，失败清理临时副本但不删除原件；附件访问校验对象归属。
- **V14：** 同一 kind+id 自动引用应更新当前引用版本，不追加重复项。为保留五条上限，新增来源将超限时打开可见选择面板并指出必需来源，让用户替换可选项；不静默丢其他引用或另开会话。会话历史引用与当前待发送引用分开。

## Q05 已确认：记录与派生要事不共用会话

记录 A 生成要事 B 后，各自保持独立的固定搭子会话，不沿用、不合并。来源关系仍保留。2026-10-08补充确认：资料库文件也采用固定会话。首次从文件进入搭子时建立关联并引用文件；以后重复点击、刷新、跨天进入均恢复原会话。改名或更新正文不改变会话；不同文件按稳定来源ID区分，同名文件不合并。

## Q04 已确认：统一项目入口

用户已在对话中确认：点击 PersonalAgent，可以一起找到相关笔记、要事、项目文件及其他项目内容；不同来源的搭子会话各自保留，不合并。

共享 project 使用稳定 ID；项目类别显式关联 projectId，各模块按同一 ID 查询，不能用名称相同猜测关系。入口按内容类型分组且可分页，分别显示空/加载/失败，部分模块失败不能把整个项目说成无内容。旧项目字符串保留，映射不明确的先显示待关联，不静默合并同名项目；改名不改变 ID、引用或 threadId。聚合页面不等于把项目全量资料送入每次聊天，模型仍按问题、范围和预算读取。
