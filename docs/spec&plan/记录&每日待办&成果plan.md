### REC-P06 · P1 · 固定分类与开发项目类别

- 对应需求：REC-09；联动 REC-08 / CHAT-08 的稳定来源关联。
- 工作：核对现有项目/标签结构后，增加独立的记录分类实体与稳定 categoryId；幂等初始化九个固定类别，保持用户指定名称及顺序。提供开发项目类别的新建、名称编辑、记录归类及按类别筛选；新建/编辑/导入共用分类校验，不为每个入口各写一套。
- 迁移：备份后保留现有 note ID、正文、附件、标签和项目关联；无可靠分类的历史记录显示待分类，支持用户批量归类，不凭模型猜测全库分类。项目类别与现有 project 的关联按实际结构显式处理，不只按名字自动合并。
- 体验：按已确认单分类与 AI 自动归类实现；自动分类失败保留待分类原文。人工纠错同步写问题表，不能等下一次开发才补登记。新建类别校验空名、重名，失败保留输入；分类调整不重新建立搭子会话。
- 完成证据：REC-A08；最小验证涵盖九类初始化幂等、项目类别创建/改名、筛选与保存、历史迁移/批量归类，以及改类后 threadId 保持。仅验证相关网页与接口，不跑手机端或无关回归。

### REC-P07 · P1 · 本地优先的录音转写与总结

- 对应 REC-10 / REC-A09。先核验可用硬件、中英文 ASR 与说话人分离组合，再选本地优先、免费优先的实现；不把 Qwen Embedding 当语音模型，不自动订购服务。

## 4. 数据兼容与失败处理

- 需要迁移时先保存一致性备份和 schema/version 信息；旧实体/引用/文件 ID 保持可解释，迁移可重入。只加兼容默认值，不伪造历史确认或完成状态。
- 先在隔离 DATA_DIR、临时来源目录和模型桩验证错误路径，不清空在线数据或用真实 E 盘做删除测试。
- 对外部服务不可用、缺密钥和人工确认等待，写明受影响的步骤及恢复条件；继续能独立完成的步骤。不能用假结果代替外部验收，也不能无限重试消耗模型。
- UI 保留输入并显示操作状态、失败原因和恢复入口；已有主题、Markdown 阅读和长内容滚动不因改动退化。

## 5. 最小验证集

按改动选用 `tests/api.test.mjs` 的相关 name pattern，以及 `tests/e2e/core.spec.ts`、`scroll.spec.ts` 中对应桌面用例。一次覆盖原文/图片/成果路径即可，勿跑原生桥和手机套件。

涉及 TypeScript 时运行 `npm run check`；准备交付网页变更时运行一次 `npm run build`。浏览器仅选相关桌面测试，例如 `bash scripts/test-browser.sh <对应测试文件> --project=desktop`。不运行 mobile、android、native-bridge 或无关全套回归；已有通过结果可复用，只有新增改动/失败才重测相关部分。

将实际命令、结果、失败修复、剩余未验证项记入模块交付记录。spec 验收表中的案例要逐项有结果或明确依赖说明，不能仅写“测试通过”。
