# 记账过滤与校验补充（不修改用户原文）

日期：2026-09-29。配套 [用户 spec & plan](spec&plan/记账spec&plan.md)；本文件补充校验落实和验收，不改变固定分类及预算，按用户 Q11/Q12 最新答复补充口径，未答细节仍明确列出。

## V01

风险：模型返回 null、字符串数组、过长标题、未知枚举或额外状态字段；草稿能填入，保存却失败。

约束：模型返回值先校验对象结构、类型、长度、枚举及引用。标题/摘要/分类等业务内容超限不能无提示截断；无效必填字段显示具体原因。模型不能写 priority、confirmed、active、revision 等人工/服务端字段。关联建议可过滤去重，但必须返回被移除项的原因；用户已确认输入不能静默过滤。

实施与验收：模型返回 null、错类型、超长正文、非法枚举和越权字段：无副作用，错误可定位；合法响应可直接进入相同保存校验。

## V02

风险：已选对象被过滤、翻页或删除后，控件不显示但请求仍携带；用户无法取消，只看到笼统报错。

约束：候选列表、已选列表和提交校验共用类型/空间/状态/自身排除规则；候选缺页不代表对象失效。已有选项即使不在当前页，也须显示摘要或失效占位及移除入口。提交时重新核验，失败保留草稿，按字段及具体 ID 返回原因。

实施与验收：选中后翻页、删对象、切换类型：仍可看见与移除旧选项；合法选择提交成功，无隐藏阻塞项。

## V22

风险：日期是文本而非Excel序号时跳过；金额/状态不能解析也直接略过；用户看到导入成功却不知道漏了账。

约束：逐非空原始行保留行号及识别/待核对/明确排除/重复状态、原因；汇总数量可与原表核对。支持约定的文本日期和Excel日期格式，非法不能被日期自动进位。存在未处理行时不能称全表完成；错误行不参与统计。

实施与验收：序号日期、文本日期、无效金额和未知状态混合样本：每行可查去向；无静默丢账或错误日期入库。

## V23

风险：同天两笔同金额同商户被误删；截图/Excel跨来源重复又未识别；退款和还款重复计算。

约束：来源渠道与交易ID作为重复依据，按Q12提交用户核对；无强ID同样不能按粗略相似键丢行。同次提交重试只做操作幂等，不等于独立导入自动去重。预览确认绑定导入批次/行ID及修订，提交再查重。Q11 已确认退款流水不计、转账计入、花呗按还款记录；Q12 已确认重复项等待人工核对、保留原件；程序统计仅包含已确认有效条目。

实施与验收：两笔合法同额交易不丢；同一确切交易重复提交幂等；预览后库变化仍提示冲突而非重复记账。

## V24

风险：OCR/AI给出分类别名或错类型类别，前端看似填写但保存拒绝；默认“其他”把识别失败伪装成确认；金额两种字段互相矛盾。

约束：收入/支出分别用明确固定集合，显示文案与存储值映射一致（例如“其他支出”的解释不是新增类别）；金额按一种规范表示，多个金额字段冲突则拒绝，不靠优先级静默选。AI未知项保持待核对，不能自动视为用户确认；统计从服务端确认数据计算。

实施与验收：错类别/跨类型类别、浮点边界、金额字段冲突、识别失败：可修正且无自动入账；确认后的统计与列表一致。


## Q11/Q12 已确认的业务口径（覆盖本文件旧的待讨论描述）

- 退款流水不计入收支统计；保留原始行并标明排除原因，不静默删原件。用户未明确是否同时冲销原消费，因此不自动修改原消费；这是剩余细节，不把“退款不计入”擅自改为“退款计收入”。
- 账户间转账需要计入，按已确认方向进入收入/支出；不能套用一般账本规则自动排除本人账户互转，也不自动净额抵销。
- 目前不涉及其他信用还款；花呗按还款记录记账，花呗消费阶段不要再计同一笔消费，生活费范围仍包含花呗。原始消费行保留对应排除/待核对状态，识别不确定时让用户核对。
- 原始 Excel 账单及截图必须保留，并与导入批次、提取行和最终交易关联；OCR 不能继续只存提取字段后删除原图。存储在 PersonalAgent 数据目录，保留下载和查看入口。
- 金额和来源相同的疑似重复项等待用户核对，不自动跳过或自动删除。即便发现同源交易ID，独立导入时也作为明确重复依据展示；由用户确认保留/跳过，再入账。来源保留支付渠道、交易对方和原始交易标识，不能仅用一个模糊字符串解释所有情况。
- 同一次已确认提交的网络重试仍由操作幂等键返回原结果，不反复创建交易或要求再次核对；这与新一批导入时的业务去重不同。

## 对应实施与验收

1. 解析阶段逐行记录识别结果、原件、行号和排除/待核对原因；退款、转账、花呗处理遵照上述规则，金额继续以分计算。
2. 新增持久导入批次、原件/截图附件关联和重复候选；确认请求绑定批次版本与用户逐项决定。待核对不进入统计，不能用默认分类冒充已确认。
3. 验证退款不入统计、转账入账、花呗按还款记录计入且消费不双算；验证数额来源相同会等待确认，同一提交重试不重复，重启后原件可回看。
4. 与 SET 完整备份和 PET 月度提醒契约联验；不改写用户原始 spec&plan 文件。
