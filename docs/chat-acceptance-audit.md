## 已修复、仍需联验的条目

1. **CHAT-A04 普通任务丢引用（已修复计划输入与快照，网页验收通过）**：WorkTasks 创建提交 taskDraft.references；createWorkTask 通过 work-task-context 校验来源类型、状态和版本，按问题选段，并复用完整话题摘要/未归纳原文。模型输入带完成要求；返回后重新核对来源及话题签名再保存待确认计划。任务详情展示当时来源版本、片段和话题背景。此次未扩展独立ACT权限/执行场景；普通任务现复用分页材料选择器（上限5条），可查看/移除已选版本、重选当前版本；来源话题可解除，引用与话题保存在当前草稿状态，不随共享缓存清理而丢失。10月8日普通任务创建及失效引用恢复网页用例通过，详见文末。
2. **调研草稿来源未清理（已修复，网页验收通过）**：ResearchCreate 的 initial.threadId 在挂载时固定；finish 清题目、问题、引用和 sessionStorage，却不清 initial。第一次调研后再创建会沿用原话题；背景、约束等也未重置。现已将来源初始状态改为可清理状态；成功后清空来源话题、背景、约束、时效、问题与引用，并恢复默认模板和输出要求；失败保留全部输入。
3. **长问题转调研字段不匹配（已修复，网页验收通过）**：搭子 query 允许2000字，ResearchCreate 同时以 initial.goal 填入主题和一条关键问题；服务端二者分别限500字。不能无提示截断原问题。现将超过500字的原问题完整放入背景，并提示填写简短主题/逐行关键问题；提交前明确校验1–8项、每项500字限制。未增加模型调用，不自动截断或猜测关键问题。
4. **当前来源候选范围（已调整并通过网页验收）**：bootstrap返回全部notes/events，因此原搜索不是只查最近记录；但匹配结果固定显示前100条，没有更多入口。现增加每次显示100条的“查看更多”，搜索/类型/重开时重置显示数量，已选引用不变；搜索加入摘要和录音转写文字。没有为不存在的服务端截断另造分页接口。
