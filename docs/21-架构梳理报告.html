〇、摸底结果

先汇报摸底结果，再逐张出图。

这个项目的真实体量（这直接决定了后面的讨论基调）：前端 63 个 React 组件、后端 78 个服务端模块、56 篇文档、一个独立的 Android 原生工程（约 2 万个文件的完整工程）、Playwright 端到端测试 + 无障碍测试 + 检索基准脚本。这不是“具备基础功能”，这是一个相当完整的单用户本地个人运营系统。

一、整体架构图

架构图里有几个值得点名的关键设计决策，它们是理解这个项目的钥匙：

  1. SQLite 是唯一权威数据源，Qdrant/Redis 都是“可重建的衍生物”——检索服务挂了、队列丢了，数据不丢；备份只需 SQLite + 文件原件。这是整个系统能放心折腾的前提。
  2. 模型层全部接口兼容、可替换——DeepSeek 只是“当前默认”，chat/vision/embedding/ASR 全部走适配层，不绑定供应商。
  3. “一致性基座”贯穿所有模块——每个业务对象都有 revision 版本号，每次提交都有 opId 幂等保护，跨端同步靠 changes 增量游标。这条横切的底线让“迟到结果不覆盖新数据”成为全系统语义。

三、模块复杂度评估

按“读懂它 + 改对它 + 出错后能否恢复”的综合难度打分：

复杂度评估的几个关键判断：

  • 榜首不是检索也不是监督，而是“数据一致性基座”（revision / opId / changes 游标 / 迟到结果核对 / 快照迁移）。它横切所有模块，是典型的分布式系统语义——在个人项目里做到这个程度非常罕见。这是项目最值钱的资产，也是最脆弱的资产：它没有独立的文档和回归测试守护，散落在 78 个模块的约定里。
  • 小九监督系统 4.5 分：条件快照（模板改动不影响已约定的历史）、证据链、每日执行记录、复盘回顾——这是一套完整的“可审计执行系统”，约 10 个服务端模块。
  • Android 端 4 分不是因为代码难，而是“双端并行”的维护成本——每个 API 契约变化都要同步两个消费方，M2 离线目标还会引入冲突合并问题。
  • 小九表现层只有 2 分——这是个好消息，说明架构方向正确：拟人化的“脸”很轻，复杂的引擎在数据侧。

四、小九 · 功能定位与实现考量

看完代码后我的判断是——小九不是桌宠皮肤，她是监督系统的拟人化前端。这个认知很重要：她背后那 4.5 分复杂度的引擎（提醒聚合 + 任务监督）才是本体，飘在屏幕上的形象只是 2 分复杂度的“脸”。这个分层是对的，别倒过来。

五个具体考量

  1. 她是这个系统唯一的“主动交互界面”。 普通功能都是用户发起、系统应答；只有小九会主动找你（要事检查、待办提醒、记忆确认、监督逾期）。这意味着所有“系统主动找用户”的功能，未来都应该经小九的口说出，保持人格一致性——而不是又冒出一个通知中心和她抢戏。
  2. 人设与机制分离。 pet-chat 已经带记忆上下文（memoryUsage），方向正确。下一步建议把小九的语气、口头禅、表情素材做成可配置的“人设包”，与监督引擎彻底解耦——换一个形象、换一种性格，引擎不动。
  3. 真实原型是双刃剑，但优势明显。 朋友的宠物、真实照片——有故事、可信、有“生活感”，这是任何虚拟 IP 做不到的。可以让她有“自己的日常”（真实宠物的新照片、小动态），和用户互相陪伴，形成任何产品都抄不走的情感锚点。
  4. 主动性要有阶梯，且克制。 现在是“应答 + 定时提醒”，且已有免打扰、去重、过度互动会“不嘻嘻”的好设计——说明你已经在保护双方。下一级是“主动发起对话”，建议只以 recap 为契机：有数据支撑的关心（“这周你完成了 4 次跑步，比上周多一次”），而不是为说话而说话。频率、免打扰、可关闭三条底线先立好。
  5. 她应该成为“阶段总结与行动建议”的讲述者。 你最初的需求“根据已有内容生成阶段总结与后续行动建议”，原料恰好就是监督 recap（证据、完成率）+ 检索 + 记忆。让小九来说这些总结，功能与角色合一，这是这个项目最自然的差异化。
⚠️ 素材授权提醒：assets 里小九的照片是朋友的宠物，个人使用没问题，但如果将来开源仓库，记得先和朋友明确授权并处理素材目录。

五、项目定位、边界与方向

定位：单用户、本地优先的“个人运营系统”，三层价值——记忆层（第二大脑：资料 + 长期记忆 + 混合检索）、行动层（外置的执行监督：待办 + 要事 + 证据闭环）、陪伴层（小九：黏性引擎）。个人工具最大的死因不是功能不够，而是弃用——小九这层恰恰是解药。

边界（建议守住）

  • 保持单用户、SQLite + 本地文件的单服务器架构——对一个人绰绰有余，且是隐私上的根本优势；
  • Android 端定位为“录入 + 查看 + 提醒”的薄客户端，暂缓 M2 完整离线第二大脑（那会引入冲突合并，复杂度直接上一个量级）；
  • 记账、OCR 这类外围模块，按实际使用频率决定投入，低频的降级为维护模式；
  • 不做多人 SaaS，不参与通用笔记软件的功能竞赛（协作、富文本这些 Notion 们已经卷完了）。

方向（按优先级）

  1. 短期——巩固：把“一致性基座”文档化并加回归测试守护（这是散落在 78 个模块里的隐性约定，最值钱也最怕无声劣化）；index.mjs 已接近 150 行 import、数千行组装，值得按路由拆分。
  2. 中期——小九深化：主动性阶梯上一级（recap 驱动的主动对话）+ 人设配置化 + 阶段总结讲述者。
  3. 长期——差异化路线：通用第二大脑市场已经很拥挤，但“真实宠物原型的陪伴 + 可审计的监督闭环”是独有的。纵深做质量，而不是横向加模块。
