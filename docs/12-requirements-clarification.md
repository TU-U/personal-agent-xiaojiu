> 更新：用户已填写 13 号答复表，并在对话确认 Q04。下文保留为当时的问题清单，不再代表全部未决；当前结果见 [确认记录](17-confirmed-requirements.md) 和各模块更新。

## 一、已经明确，不再重复询问

- 网页端与服务端；不打包或验证手机端。
- E 盘原件只读，有价值内容复制到项目内处理，未知内容保留待判断清单。
- Qdrant + dense/sparse 混合检索；Qwen3-Embedding-0.6B 本地 1024 维已确认。数据库与模型选型不重问。
- 联网失败自动调用生成 API 的已有知识继续回答，标记未联网核验；网页搜索接力是可选路径。
- 同一条记录/要事重复进入搭子，自动引用并恢复固定会话；跨天、改名、正文更新不另开。
- 九个固定记录类别，以及开发项目可自建类别。
- 要事等级由用户确定；到约定时间检查，高等级才主动复核建议，所有提醒由用户确认。
- 长期记忆人工选择与冲突确认；未确认不得生效。
- 所有监督提醒绑定小九；hover 完整提示表、常驻开关、交流/汇报/摸摸规则均已明确。
- 帮忙做事的具体场景与 Agent loop 已标待讨论，不在本次催用户决定。

## 二、文档需要修正的遗漏与冲突，不是重新向用户索要同一需求

### D01：录音总结的验收与 ASR 的优先级冲突

依据：[REC spec](spec&plan/记录&每日待办&成果spec.md)、[REC plan](spec&plan/记录&每日待办&成果plan.md)、`server/index.mjs` 的音频导入分支、`server/engine.mjs` 的归纳检查。

用户要求“上传录音/文字/图片，看到总结归纳”。当前音频导入明确返回 `needs_text`，归纳没有转写文字会报错；REC 仍将 ASR 列 P2。应把完成录音验收所需的转写纳入记录链路。资料库的全盘音频索引可以另定范围，不能混为同一优先级。

需要同步：REC 转写状态和步骤、SET 的 ASR 配置/能力检测/日志、录音原件—转写文本—总结三者关系及验收。ASR 的具体体验和服务约束见 Q01。

### D02：ACT 待讨论，但其他模块仍写“先完成 ACT-P0”

依据：[RES spec/plan](spec&plan/快速学习与调研spec.md)、[SUP spec](spec&plan/监督与督促做事spec.md)、[总索引](spec&plan/README.md)。

总索引已限定共享执行器可以按其他已确认模块的需求补齐，部分模块仍有旧的硬依赖。应把必要的计划持久化、恢复、取消和工具结果保存单独列为共享工作，不能因此启动整套未确认的“帮忙做事”，也不能把调研和监督全部卡住。

### D03：“DS 联网”与现有应用内搜索不是同一个实现

依据：[RES spec](spec&plan/快速学习与调研spec.md)、`server/web-search.mjs`。

当前应用内搜索实现为 Brave，生成模型用于整理；DeepSeek 网页是手工交接。用户早先说支持 DS 联网，文档不能在没有解释和验证的情况下把 Brave 等同于这个能力。需明确产品到底要求指定搜索提供方，还是要求“应用内能联网 + DS 网页入口”。联网失败降级规则本身已确认，不重问。具体服务能力需实施前查官方文档和做实际验证，本次不作未核实的 API 能力断言。

### D04：记账原文与计划存在局部不一致

依据：[用户记账文档](spec&plan/记账spec&plan.md)。

- 正文要求手工上传微信/支付宝 Excel，同时范围表写不做账单导入。根据前文“不涉及自动导入”可优先解释为不接账户自动拉取，而不是排除手工上传；需要在旁注中统一说明，不改写原文。
- 例子中的“餐饮”应对齐明确列出的“美食”，不应增加分类。
- 原 plan 的基础 CRUD 步骤未充分展开 OCR、Excel 分类确认、生活预算、图表排行和月度提醒；这些不是新需求，要补实施映射。
- 代码已有微信表格解析和单笔截图 OCR 入口，不代表支付宝、多笔截图、真实视觉模型及全部账单口径已经验收。后续不能把它们全部当未实现重做，也不能把入口当验收通过。

## 四、技术项由工程补齐，不必让用户逐项决策

- **服务能力与资源验证：** 检查配置的生成模型是否实际支持图像、ASR 提供方与运行条件；Qwen 型号已定，只需实测本机资源与索引质量。不能把文本 API 测通当全部能力可用。
- **长任务处理：** 转写/OCR/索引/调研需要异步进度、取消、失败恢复与来源版本；具体队列实现和事务设计属于工程责任。
- **上下文预算：** 明确 token 预算、摘要覆盖检查、来源变更后摘要失效与最新引用优先级；旧聊天不得把旧来源内容冒充当前事实。无需用户决定截几轮或用哪个唯一索引。
- **冲突检查降级：** MEM plan 写“降级检查或阻止不完整确认”，分支仍含糊。可统一为保存候选但不激活，等待完整冲突检查后再确认，满足已有人工门槛；若产品希望例外再另议。
- **检索与分类契约：** 新分类字段需传入索引与组合过滤；项目类别与 project 的关系取决于 Q04，旧资料/记忆不能因新增字段意外失踪。真实标注样本检索的验收要求已存在，不重问数据库选择。
- **提醒的运行条件：** 当前仅网页内小九，服务运行时可持久记录到期；网页关闭时没有界面展示，电脑/服务停止时不能实时检查，重启后补检查。原 spec 已排除系统推送，不擅自新增，也不能承诺“关机仍到点提醒”。月度提醒具体时刻和安静时段可放设置。
- **备份与日志：** 新增分类、来源会话映射、音频转写、账单附件等必须加入备份和引用校验；日志及文件的体积、保留策略需有工程上限，但不自动清除用户原始内容。
