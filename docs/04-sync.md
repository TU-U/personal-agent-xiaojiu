# 手机、电脑与同步设计

> Android 阶段更新：请先阅读 [手机端实施文档](mobile/README.md)。本文件保留早期完整产品提案；当前后端实际为 Express + SQLite，Android 具体范围、接口现状与开发顺序以新文档为准。


版本：v0.2 · 2026-09-22。已确认正式手机端优先 Android，Demo 先做网页版；正式版电脑安装包尚未确定。

## 0. Web Demo 的阶段边界

同一响应式网站供 Android 与电脑浏览器访问，接统一后端与账号。Demo 验证在线记录/文件上传、两端可见、引用问答、成果编辑与记忆确认；版本校验、幂等、删除传播从 Demo 起保留。

Demo 采用在线优先模式，服务器确认前显示“尚未同步”，不承诺关闭标签页后的离线草稿恢复、后台录音或上传续传。前台录音做能力探测和真机 PoC，不可用时保留音频文件上传入口。两端同时编辑仍保留冲突内容，不静默覆盖。

下文 SQLite、离线队列、杀进程恢复与分片续传为 Android App 阶段目标；Demo 可从普通文件上传与在线拉取开始。

## 1. 客户端基线

手机 App 首发 Android；iOS 后续按需求评估，不属于首轮交付。共享业务逻辑，平台差异分别验收：录音权限、来电中断、锁屏录音、文件选择、相册、后台上传、通知。

手机本地 SQLite 保存文字、元信息、变更队列；附件保存在应用私有持久目录。确认落盘后才显示“已保存到本机”。退出应用不应丢失尚未上传的内容，登出时对未同步内容给出导出或继续同步选项。

电脑首版在线浏览和编辑，可保存未提交草稿；不承诺电脑完整离线库。后续若需要托盘快捷录音、全局快捷键、目录监听，再评估桌面安装包。

## 2. 同步协议

业务内容采用“本地操作队列 + 服务端版本校验 + 增量变更日志”。SSE 只通知有变化，可靠状态由 pull 接口取得，不把事件推送视为唯一数据来源。

```text
本地事务：修改记录 + 写入待同步操作
→ push(op_id, device_id, entity_id, base_revision, payload)
→ 服务端事务：鉴权 + 去重 + 版本校验 + 写业务 + 写 change_log
→ 返回新的 revision
→ pull(cursor) 获取其它设备变化
→ 本地事务应用一页变更后，再推进 cursor
```

客户端生成随机 UUID，重发沿用 op_id；服务端按 owner_id + op_id 唯一去重。revision 是服务端单调版本，设备时间不能决定覆盖顺序。

cursor 按账号变更序列分页；记录更新与 change_log 同事务。初次同步使用快照水位，后续拉取水位之后的变化。若 cursor 超过保留期，返回 cursor_expired，执行快照重建；先保留本地待提交操作，不能直接清空本地库。

## 3. 冲突规则

| 情况 | 行为 |
|---|---|
| 手机新建、电脑尚无记录 | 创建并同步 |
| 两端同时编辑正文 | base_revision 不匹配返回 409；保留本地草稿与服务器版本，提供对比/合并 |
| 同时修改标签 | 首版仍版本冲突处理，不做无说明的自动合并 |
| 电脑删除，离线手机之后提交编辑 | tombstone 优先；拒绝恢复原对象，可将本地文本另存为新记录 |
| 旧解析任务写回 | 校验源版本；过期结果不覆盖新版本 |
| 同一录音重复提交 | op_id 幂等；hash 仅用于本用户附件复用，不跨用户暴露内容存在性 |
| 两端同时编辑成果 | 成果使用独立 revision 与版本历史，保留两份修改 |

首版不引入实时协同 CRDT。当前是同一人的多设备接续使用，显式冲突比静默覆盖更容易验证；如果以后多人实时共写成为主需求再调整。

## 4. 附件与长任务

元信息、附件上传、解析状态分离。大文件使用分片上传，持久记录 upload_id、part 编号与校验值，完成后由服务器校验 size/hash 再入解析队列。

数据库先有 pending 资源再关联完成附件；未完成上传定期清理孤立对象。删除记录使关联上传失效，迟到 complete 请求不能让已删除资料复活。

任务在服务器运行，手机切后台或电脑关闭不取消任务。用户回前台按 task_id 查询最新状态；重连 SSE 从事件序列恢复展示，最终结果以任务记录为准。

后台同步为尽力执行，系统可能延迟或停止它。必须支持回前台和手动触发续传；定时 Agent 任务不依赖手机常驻。此限制依据 [Expo BackgroundTask 官方说明](https://docs.expo.dev/versions/latest/sdk/background-task/)。

## 5. API 草案

所有用户数据接口要求服务端认证；owner_id 从会话得到，不接受客户端指定访问他人空间。

| 接口 | 作用 / 约束 |
|---|---|
| POST /v1/sync/push | 批量操作，每条返回 applied / conflict / rejected；不伪装成整批成功 |
| GET /v1/sync/pull?cursor=… | 变更页、next_cursor、has_more；包含删除标记 |
| GET /v1/sync/snapshot | 初次与过期游标恢复，分页带一致快照水位 |
| POST /v1/uploads | 校验类型、配额，建立附件上传会话 |
| POST /v1/uploads/{id}/complete | 验证归属、校验和与资源未删除；完成后入队 |
| GET /v1/resources/{id} | 当前授权范围内的资料及处理状态 |
| POST /v1/search | query、project、date_range、types；返回可授权引用 |
| POST /v1/tasks | 模板、资料范围、要求、幂等键；返回 task_id |
| GET /v1/tasks/{id} | 状态、阶段、错误与成果引用 |
| POST /v1/tasks/{id}/cancel | 幂等取消，阻止后续可见写入 |
| GET /v1/events | SSE 变化通知，不能替代 sync/pull |
| POST /v1/memories/{id}/confirm | 候选确认，带 expected_revision |
| POST /v1/exports | 导出原件、正文、记忆及引用映射，异步任务 |

Resource、Artifact 的增删改统一走同步命令；业务命令产生的 Task、Memory 等变化同样进入 change_log。避免一套 REST 写入绕过同步日志。

## 6. 第一轮必须通过的真机验证

断网录音后杀进程重开仍有文件；传到一半切网可以续传；同账号电脑看到记录和处理结果；手机退后台期间服务器继续生成；双方改同一段不会丢任一版本；删除传播后离线旧编辑不能复活；游标过期后未同步草稿保留；账号切换不泄漏上一账号缓存。
