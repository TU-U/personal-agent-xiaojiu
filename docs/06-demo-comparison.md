# Web Demo 对比与实现决策

更新：2026-09-22。对比依据为官方功能说明与公开仓库，不把开源项目宣传或截图当作性能实测。拾光自身以仓库内自动化测试和浏览器截图为依据。

## 对比对象

| 参考 | 公开能力 | 本 Demo 的实现与取舍 |
|---|---|---|
| [Memos](https://github.com/usememos/memos) | 快速短记录、Markdown、时间线、标签、置顶与自托管；仓库标注 MIT | 借鉴“先记下来”的低负担入口。拾光标题可留空，正文生成标题，支持筛选、置顶和编辑。新增来源问答和候选记忆确认；不做公开发布或社区流 |
| [Karakeep（原 Hoarder）](https://github.com/karakeep-app/karakeep) | 集中保存链接、笔记和图片，提供 AI 标签与全文搜索 | 借鉴统一收集与类型筛选。Demo 已支持文档、文字、图片、音频原件；没有把网页抓取、自动 OCR、浏览器扩展或原生移动端算作已完成 |
| [Khoj](https://github.com/khoj-ai/khoj) | 自托管个人 AI、个人资料与互联网问答、自定义 Agent、研究自动化 | 借鉴问答引用和任务成果。Demo 只访问用户显式导入的本空间资料，先做周报与主题整理；不提供自主联网研究、外部工具执行或定时自动化 |
| [闪念贝壳](https://ideashell.com/index-cn.html) | 官方展示手机/电脑记录、个人记忆、Agent 和内容生成 | 保留手机记录、电脑整理的方向。当前交付响应式 Web，Android App 未开发；不宣称达到成熟产品的全平台能力 |
| [Mem0](https://github.com/mem0ai/mem0) | 面向 Agent 的持续记忆基础能力 | 本 Demo 使用应用层可审阅记忆表，候选→确认→生效→暂停/删除。来源更新会要求重新确认，来源删除会失效。暂未引入额外记忆服务 |
| [llama.cpp](https://github.com/ggml-org/llama.cpp) 与 [Qwen2.5 GGUF](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF) | 可本地运行量化模型，提供兼容接口 | 本地推理候选，用真实问答和写作检查效果。小模型结果必须过结构、重复与引用编号检查；不合格时明确提示并返回原文摘录/整理 |

## 这轮没有直接 fork 的原因

产品流程、记忆可审阅规则和跨端版本冲突是本轮需要验证的内容。自己实现较小的数据边界更方便测试，也避免一次引入多个完整产品的运维栈。参考仅用于设计，未复制上述产品的 UI 源码或品牌资产。

## 与初始设计的差异

- 后端采用 Node.js + Express + SQLite，复用当前环境的 Node 24，降低 Demo 启动成本。正式多用户服务仍可按原设计迁移 PostgreSQL。
- 首版使用中文词切分与关键词检索，不宣称已完成向量或语义检索。以精确编号、中文关键词和无证据问题验证。
- 解析使用 pdf-parse 与 Mammoth，直接支持文字层 PDF 和 DOCX；扫描 PDF 提示补充正文，图片/音频保留原件并允许手动补充描述。
- 同步采用统一服务器 + 4 秒变更检查 + 获取最新快照。适合小型个人演示，不是正式版大数据增量同步协议。
- 保存使用 revision 校验；冲突保留本机修改。网络失败保留当前输入，浏览器草稿作补充；未实现 Android 原生离线队列。
- 访问控制是一个个人空间的共享口令与会话，手机电脑复用同一空间，不是多租户 SaaS。

## 体验侧的迭代

初始界面的浅色文字未通过对比度检查，随后调整为背景柔和、文字清晰；字体改为本地资源，消除外部字体请求。宽屏使用三列卡片，小屏使用一列；保留底部手机导航、独立输入弹窗和原文侧重的详情界面。

检索第一版连续汉字切片会误匹配“的三”等跨词片段，已改为词内匹配并加入反例测试。草稿恢复从渲染后的副作用恢复调整为初始化读取，保存期间关闭按钮明确禁用。

## 评价边界

本项目完成的是可运行、可持久保存、可实际导入和导出的演示闭环。没有实测上述竞品的付费账户、移动原生版本或生产负载，因此不做速度排名或“优于某产品”的结论。详细测试结果以 [验收说明](07-demo-acceptance.md) 和 artifacts 目录为准。
