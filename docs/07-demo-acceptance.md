# 拾光 Web Demo 验收说明

验收日期：2026-09-22。当前版本为个人空间 Web Demo，支持电脑与 Android 浏览器共用服务。不是已完成的 Android 原生 App。

## 启动与五分钟验收

1. 电脑打开 http://localhost:4317/ ，点击「进入演示空间」。服务未运行时，双击项目根目录 `启动拾光.cmd`，或在 WSL 中运行 `bash scripts/start.sh`。
2. 新建记录，例如「今天完成接口联调，下周计划补充异常重试测试」，选择项目并保存。刷新后记录仍在；搜索「接口」能找到。
3. 打开记录编辑，确认标签、置顶与删除可用。新建一条尚未保存的草稿，关闭输入框再打开，正文应恢复。
4. 上传一份文字层 PDF、DOCX 或 TXT，检查正文并下载原件。图片、音频和扫描 PDF 会明确提示补充文字，不会假装已完成识别。
5. 在「问问资料」提问「拾光项目正式手机端优先什么平台？」，应回答 Android，并可打开对应来源。问不存在的个人事实，应提示资料不足。
6. 在「记忆」确认候选偏好，再暂停；在「成果」选择项目生成周报，核对来源、编辑并导出 Markdown。
7. 两个浏览器登录同一空间，新增内容应在约 4 秒轮询后出现。两端同时编辑同一记录，后提交者收到冲突提示，本机输入保留。

初始演示口令 `shiguang-demo`，可在设置中更改。数据保存在 `.data/`，原始附件在 `.data/uploads/`。JSON 导出包含结构化记录，不打包附件原件。

## 本地 AI 的质量边界

0.5B 模型在测试中出现重复、缺失引用和错误编号，未采用其输出作为合格结果。1.5B 问答已能回答平台选择、资料导入风险和写作偏好；通过结构化响应限制来源编号。编号正确仍不意味着每句话一定正确，用户应核对原文。

自由改写周报曾把「下周验证」写成「已完成」。因此本地小模型写作改为带来源的逐字摘录与分组，模型只选择片段编号，程序直接填入对应原文，并依据明确的风险、计划标记分组；未通过就回退为本地资料整理稿。它是可编辑的初稿，不承诺成熟大模型的写作质量。外部兼容模型仍使用生成模式和基本引用检查，未进行真实付费接口效果验收。

## 已修复的问题

- 浅色文字对比度不足；调整正文与辅助文字颜色，字体资源改为本地加载。
- 中文跨词切片误召回无关记录；改用中文词切分并加入无资料反例。
- 草稿恢复时序导致偶发丢失；改为初始化恢复、关闭时同步保存。
- 嵌套弹窗按 Escape 同时关闭；改为仅关闭顶层。
- 隐藏 `.data` 目录附件被静态下载规则拒绝；在鉴权及路径校验后允许下载，并增加回归测试。
- 无文字层 PDF 被页码标记误判为解析成功；去除页码拼接并提示补充文字。
- 来源变更后旧记忆仍生效；现在要求重新确认，来源删除后失效。
- 模型引用不足、重复段落及本地写作事实改写；增加结构与原文校验及明确回退。

## 未完成范围

Android 原生应用、自动 OCR / ASR、向量检索、可靠离线同步、后台录音、主动提醒与外部工具执行均未实现。浏览器录音要求安全上下文：电脑 localhost 可用；手机普通局域网 HTTP 应使用文件上传，录音需 HTTPS。

局域网手机访问使用电脑局域网地址的 4317 端口，是否可达取决于 WSL 网络与 Windows 防火墙；本轮未宣称实机互通已验证。当前共享口令是一个人的多个设备共用空间，未实现多用户权限体系。

本轮仅使用模拟资料与测试附件，没有扫描或修改 E 盘目录。最初产品参考图片仅作只读查看。
